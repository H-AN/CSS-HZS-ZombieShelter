刀采问题的根因是 CS:S 实际刀 `TraceAttack` 使用 `DMG_BULLET | DMG_NEVERGIB`，数值4098；旧判断只接收 SLASH/CLUB，导致真人挥刀被拒。0.1测试通过主动调用 SDK 伤害钩子注入 SLASH，并未覆盖真实客户端武器路径。本轮保留武器身份、冷却及已注册受击实体校验，接纳实际刀伤害标志；距离和命中由引擎真实刀轨迹及挥刀体积判定，不再用额外AimedEntity准星直线复查拒绝合法刀击。真实客户端已完成5次刀采和10次修复命中验证，见下方独立live证据；这部分不沿用旧注入用例结论。

## 主体与外部的分工

| 主体已有能力 | 外部接入 |
| --- | --- |
| 普通怪生成、死亡、原生Reborn | 创建forward登记EntRef，按白天/黑夜目标数停放或随机合法T点启用 |
| 最近玩家索敌与行走 | 读取CHostage.m_leader，沿用主体目标 |
| 自定义动画API | 近墙时播放模板attack_anim，模拟建筑耐久伤害和声音 |
| 玩家复活、全灭检查 | 不另设复活timer，接Han_OnZombieWin执行统一失败策略 |
| Han_SafeDamageZombie | 自动设施通过存活合作玩家归因，使用实际死亡forward |
| Stage.customzombies | 开局一次固定Boss，公共名字识别，初始化后0.1秒定位 |

主体 `ZombieThink` 在自定义动画期间提前返回，因此动画和普通攻击互斥。外部只处理墙接触过渡、建筑攻击与必要的伤害保护，没有另写追人AI。离开接触或建筑毁坏后释放动画并恢复主体移动。Boss休眠自锁冻结，有效HP下降后唤醒；日夜切换不移走Boss，自动机枪/火焰塔跳过未唤醒Boss。

普通怪注册容量256，原生普通池80，为死亡身体、新补怪和Boss保留重叠余量。回场检查实际NPC碰撞体积及向下34单位路径，跳过占用点；使用地图原生地面上36单位的T出生点。创建forward处于主体初始化中间，因此先登记隐藏，下一帧再操作主体物理状态。保留主体m_iName装饰引用。

## 安全区、菜单与状态保存

默认白天/黑夜各180秒。夜间脚下位置不在三处扩张安全区并集时，每秒扣1HP；`mode.cfg`可调伤害与间隔。地图配置每座基地使用本地坐标 `mins=-544 -368 -24`、`maxs=224 400 140`，水平边长768，按基地角度旋转。绿色方形每秒刷新，安全区仅免环境伤害，不能阻止丧尸战斗伤害。已毁基地在其他基地存活时保留区域，复活安全点仍优先选择存活基地。

玩家在区域中按E打开对应基地A/B/C菜单，先看等级和血量，再进入材料确认页。菜单带客户端serial、回合epoch、建筑稳定id、等级和防重复确认标识；选择时重新验证当前区域、建筑状态及操作者个人背包，防止离开区域后操作或重复收费。升级维持缺失HP差额，修复通过刀单独进行。已毁基地可显示菜单但不可升级。

材料成熟时可刀采，每次有效命中给个人背包1个对应材料，同时消耗节点一次额度；耗尽后关闭原生碰撞、隐藏并渐显恢复，恢复满额后才允许继续采集。各基地菜单提供独立共享仓库，玩家可存入个人材料，其他玩家可从该基地取出；建造/升级只消费自己背包，不直接扣共享仓库或其他玩家材料。存取需校验当前区域、容量与实际库存。建造先检查完整模型范围、平坦地面、玩家距离和出生禁建区，再原子扣个人材料，创建失败退回该玩家。机枪、火焰、围栏、地雷各有独立配置；地雷提交消耗后再造成伤害，火焰使用统一后续燃烧调度。

失败分别保存个人背包、每座基地共享仓库、基地等级/耐久、存活设施配方/位置/角度/等级、采集恢复进度、Boss HP及唤醒状态，真实回合开始重建实体。`destroy_summons_on_failure=0`免费重建存活设施，`1`清空；战斗摧毁和已爆地雷不恢复。个人背包与各基地仓库跨退天回合保留，换图重置；这些状态在同地图进程内有效。必杀Boss全死后显示结局并按地图循环换图，不伪造主体胜利通知；同帧确认Boss死亡与基地全毁时胜利优先。
