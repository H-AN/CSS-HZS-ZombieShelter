## 玩家交互与操作约束

E的优先顺序是：瞄准近处防御设施打开设施菜单；管理员瞄准基地可打开建筑管理；其余情况在安全区内打开对应基地菜单。设施确认时仍校验瞄准实体与交互距离，默认128单位。基地普通升级和仓库存取则校验玩家所在安全区，已毁基地在其他基地存活时仍可访问仓库。

任何玩家可查看其他人的防御设施，升级和拆除限建造者、无主设施的当前操作者及管理员。退出时清除原建造者归属，重新连接不会自动重新占有。管理员从E进入的操作仍要求近距离；从全部建筑列表进入可远程管理。

升级在确认时重新读取配置成本、建筑等级和个人库存，仅扣操作者个人材料。拆除默认返还实际累计投入材料的50%，逐种向下取整；免费管理员升级不增加已投入金额。普通拆除返还操作者；默认管理员拆他人设施返还在线原主人，原主人不在线或设施无主时转入共享仓库。个人容量放不下退款时拒绝拆除；自动共享入仓可使用待入仓队列。战斗摧毁和地雷爆炸不触发拆除退款。

所有菜单操作带客户端serial、回合epoch和一次性nonce；建筑操作再绑定UID与当前等级。选择时重新检查权限、目标存活、距离或区域。重复选同一确认、目标退出、换回合、建筑被替换或已升过级都会拒绝。重置当天还绑定确认时的天数，跨天后须重新确认。

## 管理员使用

游戏内存活管理员执行 `sm_zsh_admin`。默认ROOT权限，授权检查使用 `CheckCommandAccess(client,"sm_zsh_admin",ADMFLAG_ROOT)`，可以在SourceMod的命令override中调整。每次执行仍重新检查，持有旧菜单不能保留已撤销的权限。

- 重置当天：真实回合重新开始，天数不退，恢复白天倒计时和基地；保留物资、存活设施。已战斗摧毁的防御设施不会因管理员重置自动复活。
- 共享物资：选基地、材料，增加或减少10/100、设0、设置精确数量。
- 玩家物资：只列真实在线玩家，选人再选材料；目标serial过期即拒绝，不把新占同一客户端槽位的人视为原目标。
- 精确数量：先点“设置指定数量”，30秒内在游戏控制台输入 `sm_zsh_admin_value 500`。范围0至2000000000，还要满足对应容量；纯十进制校验在转整数前拒绝溢出，成功执行后不能重放。
- 建筑：每次提升或降低一级，或者确认摧毁。列表条目显示种类、UID和等级。摧毁最后一个基地会触发人类失败，管理员操作也不绕过此玩法结果。

更改个人物资、共享物资和建筑等级的执行接口独立复核权限。菜单不以“管理员打开过一次”为后续操作的永久授权。RCON可使用现有状态、昼夜、天数、发材料命令；管理员菜单需要游戏内玩家。

## 退出、待入仓与战役边界

0.3不再保留等待原账号重连领取的离线个人库存。退出时先清空个人数值，再把这笔物资提交给团队；选择玩家当前安全区对应基地，否则最近存活基地，最后任意基地。仓库满时按其他基地剩余容量分流，全满的余额保存在无个人归属的共享待入仓队列。

仓库材料详情在有余额时显示“待入仓物资”。取出腾出容量后队列自动回填；管理员调低仓库现有数量同样可能立即被待入仓物资补入。待入仓数字属于首选基地的队列展示，实际回填仍可进入其他有空位的基地。默认仓库容量0按每种材料2000000000处理，通常不会触发溢出路径。

在线玩家跨退天回合保留个人背包；离线玩家重新连接从空背包开始。A/B/C各自共享仓库和待入仓队列在当前地图战役中保留。换图或服务器重启建立新战役，不承诺磁盘存档恢复。

## 配置数量与实体预算

当前配置目录共有**18份cfg**：根目录17份，`maps/zsh_desertplant_cso_v1_d.cfg` 1份。相比0.2增加 `amplifiers.cfg`、`progression.cfg`、`management.cfg`、`entities.cfg`，完整索引在[README](../README.md#配置文件)。分目录计数不包括主体的本图Stage覆盖文件。

实体预算以 `GetEntityCount()` 的网络实体数为依据，不使用实体最高索引代替数量。默认参数为：

| entities.cfg / Budget | 默认值 | 含义 |
| --- | ---: | --- |
| construction_ceiling | 1500 | 可选建造的全服总实体门槛上限；高于1800加载时硬截到1800 |
| minimum_reserved_edicts | 248 | 默认至少预留的实体数 |
| reserve_per_player_slot | 4 | 每个最大玩家槽位的预留，包含当前空槽位 |
| reserve_per_native_npc | 2 | 每个配置的主体普通池NPC及Boss的预留 |
| transient_reserve | 64 | 武器、效果和其他瞬时实体的余量 |
| critical_headroom | 248 | 基地、采集物等关键重建仍保留的最后空间 |
| warning_interval_seconds | 30 | 达到建造门槛后服务端告警间隔 |

动态预留为 `max(248, MaxClients*4 + (普通池数量+Boss数量)*2 + 64 + 基地数 + 材料节点数)`，数值均可由配置改变。实际建造门槛是 `min(1800, construction_ceiling, GetMaxEntities()-动态预留, GetMaxEntities()-critical_headroom)`。默认1500；例如填写2000会硬截为1800，但动态预留仍可能让它更早停止建造。

以引擎总数2048、32个最大玩家槽位、普通池100、Boss1、基地3、材料节点32计算，动态预留为 `128+202+64+3+32=429`，对应门槛1619。默认1500低于这个门槛，正常按1500限制；调到2000最终仍受1619约束。配置、槽位和地图节点改变时，应重新计算，不能把1800写成无条件可用的容量。

另有 `management.cfg/Limits/max_managed_defenses=96`，独立限制存活防御设施总数。两项限制同时满足才能建造。预算在扣材料前和创建过程中复查；创建失败回退材料，不留下半个建筑。材料成熟恢复碰撞和设施重建也要检查角色占位，不能强行恢复碰撞把玩家或NPC卡住。预算保护不能替代其他插件自己的实体管理。
