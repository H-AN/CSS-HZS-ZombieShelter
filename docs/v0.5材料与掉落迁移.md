# v0.5 材料、库存与击杀奖励

实施日期：2026-10-15。外部插件源码实施记录；不代表真人或引擎验收已经通过。

## 已实施

- `materials.cfg` 独立登记 ID、显示名、说明、`kind`。本版采用上限 64 的受控存储和实际 `gMaterialCount`；旧五种 ID 始终排在 wood、iron、copper、silver、gold。
- `resources.cfg` schema 2 的 `Gatherables` 只保存采集参数。原库存容量、仓库容量、采集冷却和全部原采集字段、采集池数值原样迁移。没有 Gatherables 的 plague_core/credits 不可采集，也不需要模型。
- 运行库存、管理员材料列表、仓库存取、离线共享、成本、投入与退款按材料目录处理。全容量清零用于防止跨地图或玩家 slot 复用残留，不用于枚举有效材料。
- `zombie_drops.cfg` schema 2 统一基础与特殊材料奖励。仅英文逗号分割，保留首尾/连续空槽、未知材料原索引；材料数控制项目数；非空单值广播，多值缺项不补，尾项静默忽略。数量严格解析正整数，拒绝 cell 溢出，单项封顶 1,000,000；有限概率大于 1 夹至 1。概率 1 即使随机数返回上界 1 也必定成功。
- 局部无效项在加载时普通 WARNING 日志后跳过；整个新掉落文件缺失、语法或 schema 错误仅禁用击杀奖励。不会 fallback 旧表，也不会让坏掉落项 SetFailState。
- 公开名字与匹配条目在 NPC 登记/初始化时缓存。死亡先写 dead/settled，按注册 epoch 去重，再发奖；Boss 也先入账再判断终局。死亡回调没有磁盘读取、CSV 解析或全规则名字扫描。
- 真实设施来源由独立 RewardContext 接入；在线主人死亡仍可入账，离线/无主设施入固定 buildCore 仓库，满仓走原共享溢出队列。设施拆除不使已发榴弹或燃烧奖励改投代理客户端；过期 epoch 和无来源世界伤害不发奖。认证完成前捕获的 serial 临时身份可安全绑定同一个仍有效的 serial。
- 旧 drops.cfg 保留迁移参考但运行时没有配置 handle；旧 days/drop_profile、drop_multiplier 已从仓库配置移除，运行路径不读取。
- 总 API 版本 2、环境 API 版本 1。旧 `HZSH_GetPlayerMaterials(client, materials[5])` 明确只写五格，新版按 ID 枚举与查询，不要求玩家存活。未知 ID/非法对象输出数量清零。

## 发行新表的明确策略

公开名字读取并核对了 HZS 主体示例 ZombieData：`普通丧尸 一阶段`、`暗影芭比`、`巨型狂暴形态僵尸`、`安哥拉`、`异形斗兽`。现场使用不同公开名时应显式编辑新 Rules，不做模糊/别名/通配默认。

这些名字的基础材料独立概率为 wood 0.225、iron 0.09375、copper 0.0375、silver 0.015、gold 0.00375，数量均为 1。该组仅参考旧基础档位的单材期望；独立抽取改变了联合分布，不保留旧随机数量或后期天数倍率。普通名以外四个特殊/Boss 名还分别有 plague_core 10%、credits 100%，数量各 1。每个同名组和重复材料项均独立执行。

核心暂未强加到发行基地升级费用，避免顺带改变现场难度；集成探针对真实基地升级解析器临时加入核心费用并恢复，验证新材料成本闭环所需解析和仓库能力。

## 离线迁移工具

`tools/migrate_v05_materials.py` 只写明确的独立输出目录，不部署、不读 RCON、不启动服务器：

```powershell
& 'D:\python\python.exe' .\tools\migrate_v05_materials.py --source '<原配置目录>' --output '<独立输出目录>' --zombie-data '<当前HZS ZombieData.cfg>'
```

可导入 `migrate_materials(source: Path, target: Path, zombie_data: Path | None = None) -> dict`，与完整迁移工具组合。输出包含材料配置、迁移后的采集/天数配置、新掉落表、旧表参考和源/输出哈希报告。重复升级会逐字节保留已有用户 `zombie_drops.cfg`。未找到公开名源时生成空 Rules 并清楚告警，不伪造名字启用通配奖励。
