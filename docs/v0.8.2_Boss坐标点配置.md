# v0.8.2 补充：Boss 坐标点与循环分配

本次把 Boss 位置改为地图配置中的五个坐标点。主插件读取 `BossSpawnPoints`，不再查找 BSP 的 `info_target`、`marker_targetname` 或额外标记插件创建的实体。版本号仍为 v0.8.2。

本轮完成代码与配置迁移准备，新安全位置由下一步现场选取。迁移候选仅抄入旧坐标；缺少的槽位重复旧点，不能把五个槽位误认成五个已经验证安全的位置。当前沙漠异形旧点已有卡墙／Hull 不适配记录。

## 地图点位配置

每张地图自己的 `configs/HanZombieShelter/maps/<地图名>.cfg` 在 `ShelterMap` 根下新增 `BossSpawnPoints`，包含且只包含 `boss1`、`boss2`、`boss3`、`boss4`、`boss5` 五个子块。

每个子块使用：

| 字段 | 含义与要求 |
| --- | --- |
| `origin` | 必填，三个完整、有限的数字，范围各为 -15000～15000；表示位置 |
| `angles` | 可省略，默认 `0 0 0`；填写时需三个有限数字，范围各为 -360～360；表示朝向 |

点位按名称编号识别，点位块的书写先后不改变编号。缺槽、重复槽、额外槽、未知点位字段、缺少位置、非数字、NaN／Infinity 或越界值会给出配置错误，避免误用 `0 0 0` 或退回旧地图标记。

`Bosses` 中每只 Boss 保留独立 ID 和原有 `boss_profile` 写法，无需逐只增加位置字段。旧 `marker_targetname`／`marker` 叶可以保留供旧版本回退时使用；新版完全忽略它们，无论地图中是否存在同名实体。

## 顺序与重叠

按 `Bosses` 中有效启用条目的配置顺序分配：

| Boss 顺序 | 使用点位 |
| --- | --- |
| 1～5 | boss1～boss5 |
| 6～10 | 再次使用 boss1～boss5 |
| 11～15 | 继续使用 boss1～boss5 |

公式为 `(顺序 - 1) % 5 + 1`。配置 ID 无需连续编号，也不按字母排序。`enabled` 缺省为 `1`；设置为 `0` 的条目不占分配顺序。调整有效条目的顺序会改变后续 Boss 使用的点位。

允许多只 Boss 共享同一点，不因重复坐标拒绝配置。放置检测忽略已登记 Boss 的本体和外观实体，仍检查地图墙体、地面及其他障碍。是否能从当前位置走出、能否通过附近门洞，需要选点后的引擎验证。

每个 ID 分别保存血量、苏醒、死亡和本回合绑定状态。`required_boss_ids` 继续指定哪些 ID 必须击杀；循环共享点位不会合并击杀目标。解析不再只识别前16个目标或截断在旧512字节缓冲内。

## 数量与外部 HZS

五个点位不是 Boss 数量硬上限。原来的8条 Boss 定义限制已移除，定义表容量与 `MAX_NPCS=512` 的跟踪容量一致；实际可加载数量仍须满足普通怪与全部原生 custom 实例的共同预算：

```text
2 × initial_ordinary_count + 所有 customzombies 数量之和 <= 512
```

外部 HZS 负责实际生成 NPC。增加或禁用 Boss 实例时，原有的 `HanZombieScenarioStage.cfg/customzombies` 仍须对应调整；本功能自动分配的是位置，不会额外创建或复活 NPC。

同类型可以填写多个不同 ID，并共用 `boss_profile`。例如六条有效胖子定义对应外部 `boss_pangzi:6`；它们按配置顺序分别认领独立状态，使用点位1、2、3、4、5、1。原生数量必须与该类型的有效定义数量精确相等，数量不足或富余都拒绝配置，防止多余 Boss 被当作普通怪处理。完全停用某类型时，也应移除它的原生生成项。

保持原生解析限制：`customzombies` 整串最多511字节、最多32个逗号分隔项、单项 `key:count` 最多63字节。相同 key 的数量合并到一个项，重复 key、空项、非法数量或溢出会拒绝。配置的同一原生 key 必须对应同一公开名称，不同原生 key 也不能使用相同公开名称，以免绑定歧义。未登记为固定 Boss 的其他 custom 类型仍计入总预算。

## 迁移准备与应用边界

仓库的原地图配置已加入五槽旧点占位。其他地图候选保存在本轮报告的 `candidate_maps/local/` 和 `candidate_maps/release/`，两者分别保留现场三 Boss 与历史发行单 Boss 等原始内容，不能整份互相覆盖。

工具 `tools/migrate_v082_boss_spawn_points.py` 把五槽点表加入指定地图配置副本，并检查其余配置值未改变。使用 `--help` 查看参数。它拒绝原地覆盖、向固定测试服写入以及覆盖已有点表；实际应用时只合并 `BossSpawnPoints`，保留服主其他地图设置。

随包工具依赖同目录的 `migrate_v05_materials.py` 提供 KeyValues 解析器；两文件需一起保留，运行入口是新的 `migrate_v082_boss_spawn_points.py`。

本轮没有选取新落点、修改 BSP、改变运行服中的 Boss 位置或重载当前局。新构建与地图候选用于下一步选点后应用。原合成台、武器／材料配方、十刀工效和50＋每级30的耗电配置保持。

复核信息以 `tests/reports/v082_boss_spawnpoints_20261025/` 下的构建、VM、迁移和最终汇总报告为准。离线 VM 执行生产解析／分配／绑定／筛选函数，不能替代引擎实体碰撞、同点实际显示或地图通路验收。
