# v0.5 本地测试入口

两条路径已经由现场确认，后续直接使用，不再重新查找或询问：

- 普通 Steam CSS 客户端：`D:\SteamLibrary\steamapps\common\Counter-Strike Source`。
- 27129 录制服：`D:\css\CS2\steamcmd\steamapps\common\Counter-Strike Source Dedicated Server`。

本版自动回归另用仓库 `tests/runtime/v05_server` 和端口 **27139**。27129 保持原状、零 BOT；不能把隔离服命令发到录制服。

**交付时保留服务器和普通 Steam 客户端，供用户本人复测。** 这是用户明确要求。自动化夹具会话可以先恢复、清理；交付前须用正式 SMX 启动并保留复测会话。交付后没有用户的停止要求，不自动发送 quit、disconnect、sm_zsh_fail 或结束其进程。

正式复测入口：

```powershell
& 'D:\python\python.exe' .\tools\start_v05_manual_review.py
```

入口只操作隔离目录和 27139，确认仅正式外部插件与 HZS；正常启动 Steam 客户端，沿用 `-hijack`、RCON 和 LAN 地址，等待自然开局后保留两端进程。RCON 临时口令通过本次唯一 cfg 装入客户端内存，cfg 执行后删除，口令不写报告；用户可在这个客户端控制台直接使用 `rcon sm_zsh_status`。进程、连接地址、正式 SMX 哈希与就绪状态记录在 `tests/reports/v05/manual_review/session.json`。这个入口没有自动退出清理；异常时也保留已启动的进程供诊断。

## 复用已有方法与证据

沿用已经使用过的 **客户端 `-hijack` 发命令／执行 cfg／`+jpeg` 截图**，与 **服务端 RCON 调用测试入口** 配合。客户端命令、RCON 结果和截图各自提供不同证据；截图生成成功仍需实际查看画面。

0.2、0.3、0.4 已执行的测试报告和截图继续保留，不作废、不覆盖，也不把旧次数加到 v0.5 的新验收次数中。旧工具和用例继续有参考价值；此次必要整改是移除默认自动加 BOT、自动补 BOT、假客户端创建和自动复活，换用隔离目录及端口，并更新确实受 v0.5 规则影响的断言。不是把全部旧测试重新判成无效。

`tools/test_local_server.py --legacy-scenarios --integration` 保留旧有地图专用用例入口，必须明确请求且已有存活真人。v0.5 新测试默认不直接运行整套旧用例。

## 无客户端引擎回归

```powershell
& 'D:\python\python.exe' .\tools\test_local_server.py --integration --report-dir .\tests\reports\v05\engine_current
```

默认仅启动隔离 27139，运行调度、范围／供电、材料／掉落的无客户端用例和独立 API 消费者；不创建 BOT 或假客户端。报告中记录实际 Passed／Failed／Skipped，API 提供方卸载、消费者缺失适配及重新加载结果，以及启动 PID／退出码。它不能证明真人菜单画面或多人体验。

## 一个普通 Steam 客户端

Steam 正常运行，隔离测试服和 CSS 客户端均未运行时，直接执行固定路径入口：

```powershell
& 'D:\python\python.exe' .\tools\test_v05_real_client.py --observe-seconds 60 --rcon-script .\tests\v05_real_client_steps.json --report-dir .\tests\reports\v05\real_client_current
```

driver 沿用现成 `Start-LocalShelter.ps1` 的网络方式：服务端监听 `0.0.0.0:27139`，普通 Steam CSS 客户端连接现场已确认的以太网地址 **`192.168.0.102:27139`**，RCON 仍连接 `127.0.0.1`。仅首次执行 `jointeam 3`／`joinclass 1`；后续以 `-hijack` 控制这个现有客户端。RCON 密码只在当前 Python 进程内随机生成，不读取旧密码文件，不写入报告，不打印完整进程命令行。运行前拒绝占用的隔离测试服／端口及已有 Source 客户端，避免重定向用户其他游戏会话。

driver 等待实际游戏进程出现后，使用已确认的 `-hijack +exec` 再发送一次连接 cfg，提高命令送达可靠性。第一轮真人启动截图出现 `Connection failed after 4 retries`，证明连接命令实际执行过；不能据此断言 Steam 丢失了 `+exec`。**`real_client_02` 已实际验证 LAN 方式成功：一个普通 Steam 真人客户端、零 BOT，HZS 自然登记 101 个 NPC 并进入白天。** 后续固定沿用 `0.0.0.0` 监听与 `192.168.0.102:27139` 客户端连接，不再重新探查连接方案。

driver 记录本次拥有服务器 PID 的实际 UDP 地址／端口，并在启动客户端前向同一 LAN 地址执行 A2S_INFO UDP 探针。连接失败时尽量保存诊断 JPEG；不修改系统防火墙，不为补人数创建其他参与者。PowerShell 子进程固定 UTF-8 输出和解码，避免系统 GBK 解码中文诊断时造成 reader thread 异常。

不带 `--rcon-script` 时默认只连接、观察、截取 JPEG，再清理本次拥有的客户端和服务器。JSON 脚本支持 `rcon`、`client`、`key`、`wait`、`screenshot` 单步动作，RCON 仅允许 v0.5 测试／状态／API 命令；禁止 BOT、复活命令和分号拼接。例如：

```json
[
  {"rcon":"zsh_test v05_ui_setup"},
  {"screenshot":"categories"},
  {"client":"menuselect 1"},
  {"wait":0.8},
  {"screenshot":"variants"}
]
```

`tests/v05_real_client_steps.json` 用于本版新菜单、射线摆放、红框、材料与 API 用例；实际执行结果写入 `session.json`，截图复制到相同报告目录。旧日志另存 `previous_logs_<run_id>`，不混为本次证据。结束时只清理本次拥有的 PID 和临时 cfg，不按进程名批量停服。

同一个报告目录已有 `session.json` 时，新运行自动放入其 `run_<run_id>` 子目录，保留之前的证据。脚本中的实射用例采用十个隔离配置组和实际射击时间，夹具清理后才运行材料用例；没有原生 NPC 时明确跳过实射，不另造测试 NPC。

短画面复核使用 `tests/v05_visual_steps.json`，仍沿用同一个 driver。`real_client_03_visual` 已实际验证压缩后的目标 HUD、合法高度内红绿框共存，以及高度外红框停止而绿框保留。各次截图由实施者逐图查看，具体画面和视野限制记录在同目录 `visual_review.json`。旧 `real_client_02` 的框外截图拍在夹具自动回室内之后，保留作原始记录，不用于证明框外画面；修正后的第三次截图才提供该画面证据。

夹具临时延长观察期、暂停原有普通 NPC、调测试靶血量、关闭夹具供电限制；这些仅发生在隔离实例内，结束恢复。录制服配置和发行默认均不因此覆盖。发射统计是实际调用时刻，红框计数是构造线条与逐收件人投递次数，均不冒充 UDP 带宽测量。

HZS 源码的正常开局链为 `RoundStart → RoundFreezeEnd → Timer_ToCreateZombie → Han_OnGameStart → SpawnRoundZombie`，未发现插件自身要求至少两人的计数门槛。是否单人自然触发该链以实际日志为准；driver 只有观察到运行状态与原生 NPC 登记后才记录自然开局。若只能测试外部菜单，可显式加 `--external-day`，它只调用测试探针的外部 `StartDay`，报告标记夹具，不能当成 HZS 正常开局或原生 NPC 战斗通过。

## 现场边界

NPC 存在后，未核对匹配的 `hzs_botaddfix` 源码、gamedata 和补丁成功日志时，禁止添加／复活 BOT，也不使用 `CreateFakeClient` 绕过。当前两个新 driver 都没有 BOT 模式。运行换图使用 `changelevel`，不把初次 `+map` 当成运行换图通过，也不修复已暂缓的本地换图崩溃。

保留现场白天 20／夜晚 60、普通 100 HP、低成本采集建造、M4A1 `+0.0`。单客户端、无客户端逻辑、合规隔离 BOT、真人多人分别记录；目前没有真人多人条件不阻止开发，但不能据此声称多人已验。

## 本轮复测收尾约束

辅助补丁试验有初始字节／detour 成功证据，但随后运行期失败；按用户明确要求停止追查，guarded BOT 与 focused follow 两项最终停用。最终留服只使用正式 HanZombieShelter 与未修改 HZS 两个插件、零 BOT，不带 `--supporting-fixes`。NPC 采用外部 B 计划补最近有效真人目标；未醒 Boss 不补目标、不为兜底唤醒，隐藏池、暂停／停车仍排除。该方案不能证明引擎远距离跟随已修好，详见 [复测修正](v0.5_复测修正.md) 和 [补丁失败记录](v0.5_定向引擎补丁核对.md)。

本轮始终保留并复用普通 Steam 客户端 PID `560`；已有该客户端时使用 `start_v05_manual_review.py --reuse-client`，不再开第二个客户端。最终服务器仍在切换正式构建，服务端 PID 与 ready 状态须读新的留服 session，不沿用历史值；`followup_probe_09_final` 仍在最终回归，本段不预填通过数。manual helper 已在启动前把旧日志移入本次报告的 `previous_logs_<run_id>`，避免上一轮 shutdown 错误混入本轮；打包器保留新 `build_` 与旧 `build-` 构建日志名，历史证据继续独立保存。
