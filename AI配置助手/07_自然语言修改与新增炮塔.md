# 自然语言修改与新增炮塔

版本：v0.8.2；更新日期：2026-10-27。本文是供AI查用的配置百科，字段依据当前源码与仓库示例核对。仓库数值只用于解释，不代表用户当前文件。本文未修改游戏配置、没有新增实服验证。

## 先确定在哪里工作

| 用户提供的信息 | AI现在应做什么 |
| --- | --- |
| 真实配置路径，并要求修改 | 读该位置的当前文件，定位接受的范围，备份目标当前文件后直接最小编辑该处。 |
| 指定工作目录，并要求在其中配置 | 目录已有配置就继续改当前副本；仅空目标首次初始化复制完整示例配置树并标注来源，随后一直维护此副本。 |
| 没有真实路径或工作目录 | 先解释对应cfg、类型、字段和修改建议；请用户提供目录，不生成文件、输出目录或模拟会话。 |

用户当前数值、文件和明确要求优先。不得为改一个炮塔先套轻度/重度模板，不得把仓库示例整份覆盖到已有目标。当前文件局部损坏时，只对照来源修受影响的块或文件，不整套还原。未给出的信息才补问，每轮最多五问，问完等回答；已有明确数据直接沿用。

当前完整目标树持续作为配置结果。需要导出时，默认给用户确认完整基线加本轮差量后的完整最终配置树，未变文件保留原字节；可另给只含实际变化完整cfg的增量覆盖树。备份与结果分开。基线不全只给字段方案和缺失项，不能声称完整。完整配置仍不等于HZS、插件、地图、模型资源齐备的完整安装；演练标仅模拟，地图/Stage/Boss门槛照旧。

操作前后按 [AI工作流程](01_AI工作流程.md)、[配置字段速查](04_配置目录与字段速查.md) 与 [检查交付及微调](05_检查交付与测试微调.md) 记录范围与最小diff。不发送游戏命令，也不以热重载、换图或清局制造生效。

## 先找类型，再找字段

文件位置按用户当前树的实际层级识别；以下路径相对于cstrike：

- 普通机枪炮塔：`addons/sourcemod/configs/HanZombieShelter/turrets.cfg`，根为`ShelterTurrets`。仓库示例类型为`machinegun_basic`、`machinegun_heavy`。
- 榴弹炮塔和迫击炮：`addons/sourcemod/configs/HanZombieShelter/grenade_turrets.cfg`，根为`ShelterGrenadeTurrets`。仓库示例为`grenade_basic`、`mortar_basic`，二者不能混改。
- 类型统计位于`Types/<类型>/Levels/<等级>`，建造配方位于`BuildRecipes/<配方ID>`；配方的`output_type`必须精确指向目标类型。

用户只说“炮塔”而目标有多个类型时，先展示当前类型/名称让其选择。中文显示名可能是翻译键，不能用自己猜的名称代替内部ID。用户说“全部”还应明确是所有等级、同类全部类型，还是连榴弹/迫击炮都包含。

### 例：榴弹伤害150、间隔0.2秒

真实来源字段为：

| 含义 | 路径 |
| --- | --- |
| 一级榴弹伤害 | `ShelterGrenadeTurrets/Types/grenade_basic/Levels/1/damage` |
| 一级榴弹间隔 | `ShelterGrenadeTurrets/Types/grenade_basic/Levels/1/fire_interval` |
| 一级榴弹最大HP | `ShelterGrenadeTurrets/Types/grenade_basic/Levels/1/max_hp` |

“伤害改150”对应`damage="150"`；“血量改150”对应`max_hp="150"`，两者不能互猜。如果用户只指一级，只改一级；如果指所有等级，应先确认是全部固定150还是保留升级递增。不要自动将全部等级拍平。

仓库`grenade_basic`一级/二级/三级原间隔是2.5/2.2/2.0秒，原伤害80/120/180；这些只是来源值，实际应先读用户当前文件。间隔越小，名义发射越频繁。若用户同时说“调长到0.2秒”，而当前为2.5秒，方向与目标矛盾，应问：

> 你希望改为0.2秒、提高发射频率，还是希望间隔比当前2.5秒更长？如果要更长，请给目标秒数。

没有歧义且用户明确给0.2秒时，它在通用字段的0.1—3600秒范围内，可以写`fire_interval="0.2"`。小于0.1的正值会被生产读取归一化到0.1，不能承诺更快；0不是合法“无限射速”。0.2秒只是名义每秒5次调度，真实发射还受目标、视线、供电、游戏更新和弹丸预算限制，不能据此宣称实测每秒5弹。榴弹还受`power.cfg/Limits/max_projectiles`等现有预算约束，不能为追求频率擅自放大它。

普通机枪来源间隔是基础0.5/0.4秒、重型0.6/0.5/0.45秒，0.2也比这些更短。相同的方向核对规则适用。榴弹改伤害和间隔不需要改`Projectile`、炮口或迫击炮类型。

### 例：建造只要1木1铁

必须先确定配方。来源榴弹配方为`BuildRecipes/build_grenade_turret`，其`output_type="grenade_basic"`；机枪来源配方为`build_basic_turret`或`build_heavy_turret`。

用户明确要求“建造只要1木1铁”时，将选定建造配方的`cost`块精确修改为下面两叶，而不是在旧cost里只补两个数字：

```text
"cost"
{
    "wood" "1"
    "iron" "1"
}
```

选定cost块原有的铜、银、金、生存币等费用叶应移除，省略费用按0读取；不要保留用户明确排除的旧费用。这里只局部编辑该cost块，保留当前文件其余内容、注释及编码。

同时必须保留`materials.cfg`中的全部材料定义、其他配方费用、其他类型、`Levels/<等级>/upgrade_cost`和`Growth/UpgradeCost`。建造只1木1铁不代表升级也只1木1铁。用户说“建造和升级都只1木1铁”时，再明确升级适用等级及Growth生成等级的费用规则，不能用修改建造cost来冒充升级费用已改。

### 例：改HP和升级曲线

1. 先从用户当前类型读取`Levels`及`Growth`，确定本轮是一级、所有显式等级、某区间，还是含Growth生成的后续等级。
2. `max_hp`是最大耐久；`initial_hp`是初始耐久，缺省按该等级最大HP读取。若当前有显式initial_hp且调低max_hp后超过它，必须一并按用户意图调整，或补问初始耐久。检查每个受影响等级均满足`1 <= initial_hp <= max_hp`。
3. 某等级显式写出的字段优先。Growth是在锚点之后对缺省字段按“锚点值＋每级增量×等级差”生成，不是覆盖所有显式等级。只改`max_hp_per_level`不会重算已经显式写死的max_hp。
4. 如用户要求所有等级统一HP，要明确是否保留升级价值、是否继续开放后续等级；不能悄悄改`Growth/max_level`或升级费用。若用户确实要求扩等级，锚点、完整的1到锚点等级、终点范围和费用都要核对。
5. 改配置不回填已经存在建筑的实体HP，不创建或复活建筑，不为显示新数值重置当前战役。生效时机单独记录。

## 新增一座“使用新模型的机枪炮塔”

这里支持的是新增一个**复用当前机枪机制的配置变体**。普通机枪机制由`turrets.cfg`这个类别加载为`Kind_Turret`；不需要也不存在让用户随便填的`weapon_type`、`projectile_type`或“自定义攻击脚本”字段。当前机制是找合适目标、调整实体朝向、检查射程/视线、播放效果并调用既有NPC伤害路径。

用户要求全新弹道、爆炸、骨骼炮管独立转动、只攻击新目标类别等能力时，先解释现有配置的能力边界。这篇文档只指导受支持配置，不写SourcePawn、不改SMX、BSP或NAV，也不把新模型造型本身称为新战斗机制。

### 新增操作顺序

以下ID仅为示例，要先在用户当前文件中查重。只在明确目标位置且用户要求新增时执行：

1. 读取用户当前`turrets.cfg`，选择一份当前有效、行为最接近的普通机枪类型作为来源。通常可选`machinegun_basic`，但以用户实际存在类型为准。仓库示例仅补充溯源，不能替代用户已改类型。
2. 在同一`Types`下**完整复制**该类型为独立新组，例如`machinegun_user_01`，保留来源类型。类型名不能与现有组重复，使用不含`/`或`:`且少于64字节的清晰ID。
3. 在同一`BuildRecipes`下复制相应配方为独立ID，例如`build_machinegun_user_01`，并将`output_type`精确改成`machinegun_user_01`。更新显示名及用户接受的cost；保留旧配方。不要只加Types而忘了配方，也不要把旧配方指向新组导致旧类型消失。
4. 类型和配方都可显式写`enabled="1"`，缺省也是1；此字段必须位于正确层级。当前仓库根schema为2，但用户当前合法兼容schema不因这个示例被改写。检查现行生产加载器支持实际结构。
5. 只改用户接受的伤害、HP、范围、间隔、供电、等级和费用。复制后默认保留原Levels/Growth及升级费；若用户希望仅一个等级，则明确改成只有Level1，或一致的`Growth/max_level=1`、`anchor_level=1`，不残留高等级行。不要给未要求的等级扩展。
6. 同模型、相同scale和几何条件下，可沿用用户当前已验证的Placement/Attachments；换模型时不能直接认定旧贴地偏移、旋转角和炮口坐标兼容。所需参数未具备时，先补问并记录待补项，不向cfg写“待定”坐标或猜测的0向量。
7. 参数和资源齐全后，把新增两块合入用户当前完整cfg，其余类型/配方原字节保持。完整解析、检查唯一键、引用和范围，再对照最小diff，交代尚未进行真实放置/射击验证。

新增后结构关系应为：

```text
ShelterTurrets（当前根与合法schema保持）
├─ Types
│  ├─ machinegun_basic / 其他现有类型（原样保留）
│  └─ machinegun_user_01（来源类型完整副本＋本轮明确修改）
└─ BuildRecipes
   ├─ build_basic_turret / 其他现有配方（原样保留）
   └─ build_machinegun_user_01
      ├─ output_type = machinegun_user_01
      ├─ enabled = 1
      ├─ display_name = 用户确认名称
      └─ cost = 用户确认费用
```

这是一份编辑关系说明，**不是可直接替换现有文件的cfg**。最终文件应保留当前完整类型、配方及其他内容。这个新增不属于轻度/重度模板原62项set，是单独接受的新增范围。

### 字段应放在哪里

以下均为现行读取器实际支持的字段；表内范围是配置校验范围，不是性能/平衡建议。只针对选定新类型编辑，不能把机枪专用字段表套给其他机制。

| 位置（在新类型下，另注明者除外） | 字段与语义 |
| --- | --- |
| 类型根 | `model`为相对游戏目录的真实mdl路径，`display_name`、`description`为显示；`enabled`控制该类型是否参与有效配方读取。 |
| 类型根外观 | `model_scale`为0.01—16，缺省1；`render_rgb`三整数、`render_alpha`、`skin`、`body`按实际模型支持情况配置。不要靠缩放推断真实PHY碰撞已一致。 |
| `Levels/<等级>` | `max_hp`、可选`initial_hp`为正整数且不超2,000,000,000；伤害`damage`有限值0—1,000,000，`range`为0—8192，`fire_interval`按0.1—3600秒核对。 |
| `Levels/<等级>` | `minimum_base_level`为正整数，缺省1；还须在用户可达基地等级范围内。它不是`required_level`，后者属于武器合成等其他配置。 |
| `Levels/<等级>` | `power_required`为0—100000，`power_priority`为0—1000，缺省10；与当前发电机和电网总负载核对，不为了新炮塔擅改发电机或power.cfg。 |
| `Levels/<目标等级>/upgrade_cost` | 升到该等级的材料费用，与BuildRecipes的建造cost分开。材料ID必须在当前materials.cfg注册。 |
| `Growth` | `max_level`、`anchor_level`；`Stats`支持相应`max_hp_per_level`、`damage_per_level`、`range_per_level`、`fire_interval_per_level`、`power_required_per_level`及合法min/max约束。负射击间隔增量要核对终点与`fire_interval_min`。 |
| `Growth/UpgradeCost` | 按材料ID的`<材料>_per_level`生成缺省等级的升级费，不能只改显式upgrade_cost就声称所有未来等级已更新。 |
| `Placement` | `mode`支持upright/surface/wall；`origin_offset`、`angle_offset`为三分量模型放置偏移，`allow_overlap`控制重叠规则，`max_distance`为16—4096。保持当前已接受规则，不用放开重叠绕过模型适配。 |
| `Placement`可选 | `model_ground_z`、`model_ground_curve_z`为已有贴地修正参数，缺省0；没有测量依据就保留当前值，不能从其他模型照抄特定修正系数。 |
| `Attachments` | `muzzle_offset`和`light_offset`为相对模型原点的三分量位置。X向前、Y向左、Z向上，按实体最终角度变换；不是地图世界坐标，也不是可随意填写的骨骼名。 |
| `Sounds` | `build`、`attack`、`upgrade`、`destroy`等用实际可用sample；本例复制当前已可用声音，用户未要求则不擅改。 |
| `Downloads` | 每个唯一子键的值是一条真实资源相对路径。加载器只把存在且路径合法的文件加下载表，不负责创建模型或修复缺资源。 |
| `BuildRecipes/<新配方ID>` | `enabled`、`output_type`、`display_name`和`cost`；output_type须精确指向新类型，材料费用为有效非负整数，各叶不超1,000,000。 |

向量必须是三个完整有限数字，通用元数据读取各分量范围为±8192。这个范围只表示语法/边界通过，不证明朝向、支撑和炮口正确。机枪实际伤害还有既有伤害API上限及成长/增强器影响，不能用配置damage直接宣称最终实伤。

新增类型/配方仍占用既有配方目录上限（当前256）与实际建筑/实体预算；`max_per_base`不是机枪新增独立限额开关，不能因通用等级解析器认识该字段就承诺炮塔按它限数。不要在普通机枪类型里写榴弹的`Projectile`、`projectile_speed`或`blast_radius`并宣称产生榴弹机制。

### 新模型还缺什么

新模型路径只能来自用户或已确认文件，例如：

```text
model = models/<用户确认的目录>/<用户提供的模型名>.mdl
```

这是占位说明，未给真实路径时不能写入cfg或生成假模型文件。拿到一份mdl仍需核对：

- 它是否为当前CS:S兼容模型，游戏搜索路径内能否找到，以及实际使用的vvd/vtx/phy等伴随文件和材质贴图；按真实清单列Downloads，不凭文件名机械编造不存在的伴随资源。
- 服务器文件存在不代表客户端资源已下载可渲染；材质引用和音效也要按真实资源核对。模型格式或资源缺损是资源问题，不承诺只改配置就能修复。
- 贴地原点、缩放、支撑/碰撞和局部朝向能否沿用当前已验证模板；不能把另一模型的特定offset、PHY假设、旋转修正直接复制。
- 炮口相对位置及方向、实际出射视线是否正确；`Attachments/muzzle_offset`不会自动识别模型里随便命名的炮口附件。最终实体朝向与模型本身前向需协调。
- 是否存在所需动画与skin/body；本文不制作模型、不烘焙变换、不添加骨骼动画，也不改源码或BSP完成造型适配。

若用户只要求换模型，但未给定位和支撑信息，保留待补说明；只有已经证明与原模板兼容，或拿到用户明确的测量结果，才沿用对应参数。配置语法通过、文件存在、模型可预缓存和真实放置/炮口/射击通过是不同状态，逐项记录，不互相冒充。

### 新增时的分轮补问示例

只问当前确实未知的项；用户已经给出的答案不再问。

路径或机制未明确且确实影响本轮操作时，先单独澄清；已给出的信息不再问。下面每一条只是一项独立决策，不把多个统计值塞进一个编号。

数值第一轮最多五问：

1. 新炮塔的显示名是什么？内部ID由AI给不冲突的建议，用户有指定则沿用。
2. 基础伤害设多少？
3. 发射间隔设多少秒？方向与数值冲突时先澄清。
4. 基础最大HP设多少？
5. 建造需要哪些材料、各多少？这是一份建造费用表，升级费用另列。

收到回答后，仍需确认的参数放下一轮，最多五问：

1. 攻击射程设多少？
2. 开放几个等级？各等级的细化数值有需要再分轮问。
3. 建造解锁需要基地几级？
4. 电力需求设多少？
5. 电网分配优先级设多少？

模型尚不完整时，再按真实缺项补问，每轮最多五项，例如真实mdl路径、兼容放置来源、贴地参数、局部朝向、炮口位置各占一问。能从用户提供目录直接读取的资源清单先只读核对，不要求用户重抄；光效位置、升级费用或其他未决细节另放后续轮次。默认值可作为单项建议，不将一长串未给参数捆成“全部是否沿用”。

若用户只要“把当前grenade_basic一级伤害改150”，且路径和等级已给，就直接执行那个字段的局部编辑，不重问这些数值。无路径时只解释相应字段并请给目录。

## 完成时告诉用户什么

- 改了哪个当前文件、哪个类型/等级/配方、具体旧值到新值，是否有新增两块；列出必要的局部删除，如cost里排除旧铜费用。
- 已有当前完整树保持，未动其他类型、材料定义、用户后续自定义和真实地图；文件层面检查与资源/运行未验证项分别写清。
- 如果尚缺模型参数、完整基线或地图前置，只说明还缺什么，不告知“已部署可用”。无路径时本轮没有输出文件。
- 多数cfg在战役建立后锁定，用户自行安排新的加载时机；本文不发送重载/切图命令，不改现存实体，不重置库存/战役。后续微调继续读取当前副本，局部修，不重套示例。
