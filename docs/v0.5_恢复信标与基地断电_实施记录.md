## 配置与菜单

新增四份可选配置：`repair_stations.cfg`、`heal_stations.cfg`、`armor_stations.cfg`、`beacons.cfg`。缺少某份新配置时不因此关闭整个旧模式；已有新配置升级时按字节保留。各文件继续沿用 `Types`、`BuildRecipes`、每类多变体、`Levels`/`Growth`、材料 ID 费用和现有模型/颜色/skin/音效元数据，不为每个变体单独硬编码行为。新增建筑枚举追加为 AutoRepair=10、Heal=11、Armor=12、Beacon=13，旧枚举数值不变。

建造仍走类别→变体→详情→确认。详情与升级页显示恢复量、间隔、耗电、当前同组数量及有效上限；确认前显示当前射线归属基地，同组满额时禁止新增确认。服务器提交再次校验限额。已有设施仍可管理、维修和升级。

| 字段 | 契约 |
| --- | --- |
| 根 `Limits/max_per_base` | 同一基地、同类的所有变体共用上限；三类恢复默认各为 2，信标固定为 1 |
| 等级 `max_per_base` | 有效值取根共享上限与当前等级值的较小值，无法用变体绕过共享上限 |
| 等级 `restore_amount` | 每次脉冲恢复的整数数量；不超过目标缺失值 |
| 等级 `restore_interval_seconds` | 默认 20 秒，最低 1 秒；`Growth/Stats` 可按等级调整并配置上下界 |
| 等级 `power_required` / `power_priority` | 使用原基地电网的整份供电分配与优先级 |
| `Sounds/pulse` | 实际发生恢复时播放；空字符串关闭音效 |

存活的逻辑设施在等待实体恢复期间继续占组名额。计数按固定 `buildCore` 和建筑类别，包含同类不同模型/配方；除组上限外，原基地建筑配额与全服实体预算仍生效。

当前新增默认配置的初级恢复设施为每 20 秒恢复 1、耗电 5，高级为每 10 秒恢复 5、耗电 20。三类各有初级和高级变体，最高 3 级；等级恢复量、间隔、HP、耗电及费用从配置读取。该组新默认值不覆盖旧建筑的现场数值。

## 三类恢复的范围和节奏

- 自动维修：仅恢复固定所属基地当前红色建造矩形内的存活、受损建筑，以保存的建造锚点检查范围；扩大器改变当前红框时，维修范围随之变化。建筑保留所属基地，停止维修框外目标。
- 治疗：只恢复固定所属基地原绿色安全区内的存活真人生命，以玩家有效最大生命限制补足；现有额外生命不会被削减，不复活玩家，不治疗 NPC。
- 护甲：只恢复固定所属基地原绿色安全区内存活真人的护甲，上限 100；不处理 BOT、死亡玩家或观众。

三类均要求设施和所属基地存活且当前供电有效。世界 Timer 保持 0.25 秒；每座设施保存独立 `nextRestore`，到期只执行一次并推进到下一间隔。无人需要恢复或设施离线也推进期限，恢复供电后不累计补发旧脉冲。只有至少一个目标实际获得生命/护甲/耐久时才发送效果圈及 `pulse` 音效。效果圈属于恢复反馈，红框与绿区规则保持原有职责。

## 防御工事与照明旋转

仅防御工事和照明支持垂直 pitch、水平 yaw，每次 **+10°/-10°**。初次瞄准按 E 后选择轴；轴菜单持续保留，返回管理与换轴继续绑定同一 UID、generation、等级、serial、epoch、配置修订和权限，并检查实际旋转后 OBB 最近点交互距离。初次 E、升级、拆除和工事接管仍检查实际瞄准。

旋转更新保存角度、实体角度及恢复边界，保留模型偏移和建造锚点，不再扣材料。照明的光源继续作为模型子实体，使用配置 `Attachments/light_offset` 的本地位置和零本地角度，让父实体旋转后得到正确世界位置/角度。

首轮真实测试发现照明子实体把世界坐标写进本地坐标，造成位置重复相加；测试辅助函数还误读了 CS:S 不存在的 `Prop_Send m_hMoveParent`。生产修正与测试修正分别处理：父实体通过 `Prop_Data m_hMoveParent` 或 `Prop_Send moveparent` 读取；即时测试核对本地 offset/零角并派生世界变换，延迟真实 UI 验证再读取 `m_vecAbsOrigin` / `m_angAbsRotation`。probe02 已通过：光源期望、派生及真实绝对位置均为 `2556.198 -1637.556 63.058`，绝对角度为 `10 110 0`；真实菜单仍显示照明的 +10°/-10°、返回和退出，原材料只扣建造一次。probe01 的实际故障记录完整保留。

## 信标和公开 API

每基地最多一座存活逻辑信标，各变体共享该位置。瞄准信标按 E 优先打开目的地菜单，只列其他存活基地中实际有效、供电且可用的信标；选择后使用该基地现有安全出生点落地事务。验证存活真人、源信标交互距离、源/目标基地及信标的身份、等级、generation、战役与配置修订、一次性菜单 nonce，速度归零，落点无效则失败。源或目标基地摧毁时拒绝传送并给出基地提示。

目的地菜单保留“管理此信标”，管理页仍可升级/拆除并可返回传送选择。信标的配置 `Marker` 使用 sprite/offset/scale/rgb/alpha 展示标记，具体可用性及菜单状态以服务端有效条件为准。

公共接口继续沿用以下两个 optional native，完整契约和商店示例见 [公开 API](昼夜求生公开API.md)：

```sourcepawn
native bool HZSH_TeleportPlayerToBase(int client, int coreUID);
native bool HZSH_ShowBaseTeleportMenu(int client, Function onSelected, any context=0);
// void onSelected(int client, int coreUID, any context)
```

基地选择 API 只回调 UID，选中不自动传送；取消/超时/失效回调 0，事务在调用仍有效插件的 callback 前消费。直接传送和信标不新增钱、积分、冷却收费或普通玩家回城命令。商店插件自行检查余额、调用传送，并在返回 true 后确认扣费；异步预留及退款由商店负责。

## 基地摧毁与电网

电网固定归属基地摧毁后，该基地发电有效输出归零，负载停止工作；恢复设施、信标、扩大器及既有依赖供电的炮塔/照明等继续通过统一有效状态过滤。`power.enabled=0` 仍要求所属基地存活，无法借兼容模式绕过基地毁坏状态。其它存活基地的电网独立工作，既有建筑保留。

原绿色夜间安全区规则继续保留：在仍有其它基地存活时，已毁基地原绿区仍按既有安全规则处理。电网关闭与夜间绿区属于不同状态，不把基地毁坏解释为全图设施删除或整张地图夜间安全区消失。
