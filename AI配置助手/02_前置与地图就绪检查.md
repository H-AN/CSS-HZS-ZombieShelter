# 按任务检查前置、地图和配置位置

适用版本：CSS-HZS-ZombieShelter v0.8.2。本文供 AI 判断本次请求需要哪些资料、应修改哪份配置。入口见 [README](README.md)，操作规则见 [01 AI 工作流程](01_AI工作流程.md)，字段查询见 [04 配置目录与字段速查](04_配置目录与字段速查.md)。

## 1. 先看用户要做什么

本目录既是配置百科，也是可持续对话修改的操作依据。用户可以直接说“白天改100秒”“一级榴弹伤害150”“把误删的配置补回来”。不要每次都从安装问卷开始，不要求先选轻度或重度。

| 本次任务 | 必需信息与处理方式 |
| --- | --- |
| 解释字段、推荐数值 | 根据当前版本直接解释；有现值就说明现值，没有就标未知。无需先索取目录或完整安装检查 |
| 单项或局部修改 | 定位本次编辑目标、当前文件、确切字段及关联约束，直接作最小修改；无目录只给字段方案 |
| 缺损修复 | 读取当前副本，优先参考其备份，再对照同版本仓库原件，只修受损部分并保留其他自定义 |
| 新增受支持的炮塔类型 | 按 [07 自然语言修改与新增炮塔](07_自然语言修改与新增炮塔.md) 收集真正缺少的配置与资源信息，每轮最多五项 |
| 首次轻度／重度整套预设 | 确认目标目录、版本来源、安装前置、地图与本图 Boss 状态，建立或读取完整副本后修改 |
| 准备实际开服、判断能否运行 | 核对安装、API、资源、地图、Boss 与本次实际加载证据；证据不足不称可运行 |

单字段解释、离线值修改和缺损修复不以整套安装完成为进入条件。初次整套预设或开服任务要先确认前置与地图；缺项时明确说明实际部署尚未就绪。用户明确先做离线工作副本时，仍可准备配置文本，不能靠编造地图或位置数据把缺项写成通过。

## 2. 配置位置分三种，已有信息直接沿用

需要写文件且目标未知时，询问一个必要的位置决定：用户可以提供真实服务端配置目录，也可以提供任意本地工作目录。服务端不在本地或不愿披露地址，不妨碍使用工作目录；不要索取账号、密码或远程权限。

纯字段查询无需先问位置。用户已明确本轮工作目录时，后续一直修改这份当前副本，不反复索取目录、不另建副本重头开始。

### 模式一：给出真实服务端位置

先只读确认实际层次，再按已授权范围直接最小修改。

| 提供的位置 | 正确定位 |
| --- | --- |
| 服务端上层目录，内有 `cstrike` | 游戏根为这个 `cstrike`，配置根为其 `addons/sourcemod/configs/HanZombieShelter` |
| 已是 `cstrike` | 在其下定位 `addons/sourcemod/configs/HanZombieShelter`，不重复追加 `cstrike` |
| 已是 `HanZombieShelter` 配置目录 | 直接修改其中的 cfg，不在里面再创建 `addons` 或 `HanZombieShelter` |
| 自定义结构或多个候选 | 结合实际文件和用户说明确认；不凭名称认定是真实服务端，不同时改多套环境 |

路径不可读时明确说明，不改其他猜测位置。目标包含只读仓库原配置时按第3节处理。写盘成功与当前战役已读取新值分别报告；修改数值的授权不等于启停、切图、重载、清局或重置库存的授权。

### 模式二：给出任意工作目录

工作目录是本次副本的编辑位置，不自动认定为真实服务端。

1. 已有配置优先。根下已是 `HanZombieShelter` 的 cfg 就直接沿用；已有 `addons/sourcemod/configs/HanZombieShelter` 就沿用该树，不多套一层。
2. 目录为空且用户要求实际生成配置时，核对版本，从可取得的同版本仓库／发行示例复制完整配置树到指定目录，再在副本修改。普通工作目录可用 `addons/sourcemod/configs/HanZombieShelter/...`；用户明确指定配置目录层次则按该层次放置。
3. 完整树保留来源中的全部配置文件与子目录。它不是完整服务端安装；配套环境配置等额外范围只有来源明确时一起复制，不凭空补齐 HZS、地图或其他插件。
4. 没有同版本完整来源时，说明缺少什么，先给字段方案；不拼接不同版本、不把少量字段或片段冒充完整树。
5. 目录已有配置但部分缺失时，按局部修复处理，区分误删和合法自定义；不以“初始化”为由整套覆盖。
6. 后续继续读写当前副本。初配后说“白天100秒”，只改对应字段，不重新复制原件、恢复模板或抹掉用户后来的手动修改。

复制的样图仍只是样图；完整配置树不证明其中的坐标、Boss五点、环境或原生Stage已经适配实际目标地图。

### 模式三：没有任何目录

只在回复中给相对于 `cstrike` 的 cfg、确切 KeyValues 路径、目标值和必要影响。例如：

```text
文件：addons/sourcemod/configs/HanZombieShelter/mode.cfg
字段：ShelterMode/Rules/day_seconds
目标值：100（秒）
```

可以推荐：“给我一个工作目录或真实配置目录，我可以直接修改，并继续在这份配置上微调。”不要猜桌面路径，不擅自创建文件、ZIP、会话记录或输出目录，不声称已经修改文件。

现值未知就说明未知。类型、等级或语义有歧义时只问必要的问题，每轮最多五项，不能把示例值当作用户当前值。

## 3. 仓库原件只用于查询、溯源和修复

仓库原配置永不作为本流程的编辑目标。用户给出的路径指向仓库示例时，说明它是只读参照，推荐一个副本目录；用户未给出副本位置前按模式三回答。检查实际路径，不能通过路径别名绕过原件保护。

有源码仓库时，[`../plugin/addons/sourcemod/configs/HanZombieShelter/`](../plugin/addons/sourcemod/configs/HanZombieShelter/) 是相对于本文的可选示例来源；也可用匹配版本安装包中的完整配置。原件用于核对根块、字段、schema和确切缺项，不用于抹掉合法自定义。

修复优先使用当前副本的备份。需参照仓库时，确认版本和结构，只补确定缺少或损坏的内容。无法判断差异是误删还是有意修改，就先说明并询问，不自动恢复默认值。

记录、候选与备份在本次用户已指定的位置按 [01](01_AI工作流程.md) 和 [05](05_检查交付与测试微调.md) 处理；没有目录则只给文本。真实服务端的游戏配置目录中不塞入解释文档或记录JSON。

## 4. 初次整套预设或开服时确认运行前置

简要说明必需项目，再确认用户已经安装哪些。可读文件先只读核对，已知信息不重复问，前置与玩法分轮，每轮最多五项。

| 必需项目 | 核对内容 |
| --- | --- |
| 可运行的 CS:S 服务端 | 真实游戏根、平台与安装来源；工作副本不算实际服务端 |
| Metamod 与 SourceMod 1.12 或更高版本 | 匹配版本与放置情况，文件存在不等于已加载 |
| HZS 主体及其依赖 | 主体实际构建提供所需API，自身扩展、gamedata、配置齐全 |
| NPC模型、材质、声音和翻译 | 与主体配置引用匹配，Shelter增量包不能替代主体资源全集 |
| Shelter主插件、配置、翻译及资源 | `HanZombieShelter.smx`、同版本配置、`HanZombieShelter.phrases.txt` 与引用文件 |
| 已处理好的目标地图 | 本图完整ShelterMap、原生Stage、配套资源与可信Boss位置 |

当前 v0.8.2 各更新ZIP属于增量交付。复制配置也不是安装全部依赖；缺少完整基础环境时列为待补齐，不称已经可以开服。

AI 内部核对：当前启动检查使用 `Han_IsZombie`、`Han_GetZombieName`、`Han_SetZombieTarget`、`Han_UnlockZombie`、`Han_SetCustomAnimationEx`、`Han_SafeDamageZombie`。伤害成长要求运行主体实际提供 `Han_OnZombieDamagePre(int zombie, int attacker, int &damage)`；Boss普通近战识别还使用 `Han_OnZombieAttack(int zombie, int victim)`。只更新源码或include不能代替运行主体能力。

有源码可选核对 [`NPC.inc`](../src/HanZombieShelter/NPC.inc) 和 [`HanZombieScenarioAPI.inc`](../src/include/HanZombieScenarioAPI.inc)；没有源码则用可信版本说明与实际安装证据。没有运行证据就标待验证，不为证明这些项目擅自操作游戏。

### 条件组件按功能检查

| 组件 | 处理方式 |
| --- | --- |
| HWS、斧头、十刀或其他武器系统 | 使用相应武器合成配方时需要命令提供者和资源，主玩法不以HWS为硬前置。命令格式正确或已派发不等于实际发武器成功 |
| `HanZombieShelterEnvironment` | 按目标地图昼夜视觉配套核对插件和配置，不假定所有地图支持同一方案 |
| NPC追击距离伴生插件 | 可选，涉及特定引擎构建与平台，不作为启动前置，不与同项补丁叠加；现有独立包仅适配已审计Windows x64构建 |
| BOT修复试验、测试助手 | 不列为依赖，不从测试目录自动安装，不添加BOT/FakeClient |
| Python、SourcePawn编译器 | 属于工具或构建环境，使用现成SMX、查询字段和本套文档不以它们为游戏运行前置 |

单改无关字段时，不因为未使用的组件缺少就阻塞修改；准备启用对应功能时再检查、说明缺项或由用户选择暂不使用。

## 5. 地图检查针对部署，不替用户开发地图

首次整套预设需要确认地图状态；仅准备工作副本且暂未确定地图时，记录“目标地图待确认”。准备真实部署时必须确认实际地图和配套，不能自动选用副本里的样图。

| 对象 | 实际部署需要确认的内容 |
| --- | --- |
| 地图身份 | 精确地图名、BSP与导航适配版本，不只比显示名；导航可能内嵌，不仅凭独立`.nav`文件判断 |
| `addons/sourcemod/configs/HanZombieShelter/maps/<map>.cfg` | 本图完整`ShelterMap`及基地、安全区、真人安全出生点、资源引用；Boss点位片段不是整图配置 |
| 本图`BossSpawnPoints` | `boss1`至`boss5`各一槽，origin三个有限数各在±15000；angles可省略，填写时三个有限数各在±360 |
| 本图`Bosses`与`bosses.cfg/BossTypes` | 至少一个有效启用定义，ID、`boss_profile`、`han_config_key`、`public_name`正确对应 |
| `addons/sourcemod/configs/HanZombieScenario/<map>/HanZombieScenarioStage.cfg` | 固定Boss每个key的`customzombies`数量与有效定义中同key实例数精确相等，同时满足共同NPC预算 |
| 实际HZS ZombieData及本图覆盖 | 按实际读取优先级核对key、公开名和资源，不能只看全局文件忽略本图覆盖 |
| 本图环境配套 | 使用已经处理好的匹配方案，不在本流程制作地图、导航或灯光适配 |

五槽不会自动生成五只Boss，只有一只也需要五槽；禁用全部Boss不能绕过当前版本规则。合法数值和五槽齐全只证明静态结构，不代替真实体积、支撑与路线验证。全零、随意复制五遍或借用其他BSP坐标，不能冒称本图指定且验收过的位置。

缺少适配或Boss位置时，告知需要先取得本图已处理好的配置，记录部署尚未就绪。仍可解释字段、修改全局数值或修复工作副本；不替用户寻找坐标、制作BSP/NAV、改光照样式、编造Stage或调用旧开发测试脚本，不为消除缺项改变Boss阵容或填占位坐标。

## 6. 分开报告配置修改与运行状态

| 结论 | 对应证据 |
| --- | --- |
| 已给字段方案 | 相对cfg、确切KV字段、值与影响；无目录时停在这里 |
| 当前副本已修改 | 已在用户指定目录修改并读回，其他自定义保留 |
| 整套副本已准备 | 同版本完整来源明确、未改文件也在树中；不等于安装或地图适配完成 |
| 安装／地图待补齐 | 明确列出未知和缺失项目，可继续离线配置，不宣称能运行 |
| 已加载／已实测 | 有本次实际证据并写明范围；用户确认、文件核对和运行验证分别记录 |

轻度／重度是初始建议，后续不必重复套模板。一直以当前副本和用户最新意图为准；反馈只改相关项，不回放旧基线，也不把静态检查或文件树完整当成开服保证。示例见 [06](06_对话示例.md)，新增炮塔见 [07](07_自然语言修改与新增炮塔.md)。
