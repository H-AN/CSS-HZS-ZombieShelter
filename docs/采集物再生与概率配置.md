# 采集物再生与概率配置

资源点在每次采空后，为下一轮重新抽取材料。位置、角度和资源池保持不变，木材点下一次可以长成铁、铜、银或金，也可以再次抽到木材；没有强制换种或保底规则。

配置位于 `addons/sourcemod/configs/HanZombieShelter/resources.cfg`。地图的 `ResourceZones/<区域名>/pool_id` 选择这里的池，不同区域可以分别使用普通资源池、矿区池或稀有资源池。无需修改 BSP 点位。

## 初始概率与再生概率

默认池保留原来的相对权重，并开启每轮重抽：

```text
"Pools"
{
    "desert_mixed"
    {
        "reroll_on_regrow" "1"
        "Weights"
        {
            "wood"   "55"
            "iron"   "25"
            "copper" "12"
            "silver" "6"
            "gold"   "2"
        }
    }
}
```

`Weights` 用于新战役的初始生成。省略 `RegrowWeights` 时，每次采空后也使用这一组权重。上例总权重为 100，因此对应 55%、25%、12%、6%、2%；如果总和为其他数值，则概率是该材料权重除以总权重。

需要“初始普通、后续更容易出现矿物”时，在池内增加独立的 `RegrowWeights`：

```text
"RegrowWeights"
{
    "wood"   "30"
    "iron"   "40"
    "copper" "20"
    "silver" "8"
    "gold"   "2"
}
```

这一段是完整的再生概率表。省略的材料等同于权重 0，不会继承同名 `Weights` 条目。显式写出的空表、全零表会拒绝加载，不会悄悄回退初始表。

将 `reroll_on_regrow` 设为 `0`，资源点会在当前材料上反复再生，兼容旧版固定种类行为。这是每个池的配置项，不是服务器 ConVar。默认值为 `1`。同一个池的多个点各自独立抽取。

权重允许有限的非负小数，零权重永远不会抽中。负数、NaN、无穷、数值后夹杂其他字符、未知材料名和全零概率都会拒绝配置。计算时先按最大权重缩放，再求和，防止很大的有限权重相加溢出。支持的材料键为 `wood`、`iron`、`copper`、`silver`、`gold`。

## 每轮的实际顺序

1. 玩家最后一刀仍领取本轮旧材料，并显示旧材料的 `0/本轮次数`，不会把最后一次奖励变成下一轮材料。
2. 当前实体立即完全透明并关闭碰撞，剩余次数保持 0。
3. 下一次已有世界更新处理这一轮的抽签。使用同一个 `prop_dynamic_override` 更新模型、颜色和缩放，不为每个资源点新增定时器，也不为每轮抽签新增实体。
4. 按新材料的 `hold_seconds` 保持透明，再按其 `grow_seconds` 逐渐显现。`render_alpha_curve` 可以为 `linear` 或 `ease_in`。
5. 成熟后使用新模型范围检查玩家、丧尸和建筑物占位。区域空出后，恢复碰撞和新材料的 `hits_per_cycle`；占位时保留本轮结果，不重新抽签。

`yield_per_successful_hit` 控制每次有效采集的基础产量，当前默认 1 个。新增武器倍率源码将其乘以 `weapons.cfg/gather_multiplier`：直接按当前武器 classname 查表，未配置回退当前普通刀行，不限制刀槽或武器名称；因此枪械有效命中资源也按对应规则采集。当前27159测试服已按用户授权重启应用这一更新，完整状态见 [06 采集倍率与音效修复](D:/gmod昼夜求生资源/文档/进度文档/v0.6.0_进度文档/06_武器采集倍率与斧头音效修复.md)。

倍率支持 `0..1000`、最多三位小数，缺省 `1.0`，`0` 禁采。按玩家和材料保存千分位余量，`1.5` 为 `1、2、1、2`，`1.1` 每10次合计11个；换武器、换节点、死亡、回滚或热读武器表不清余量，断线和新战役/换图清零。背包只发整数。基础产量和倍率计算拆分乘法，按剩余容量封顶，不发生32位整数乘法溢出。

背包满、处于采集冷却、倍率为0、未成熟资源都不消耗次数或触发抽签。正倍率小于1导致本次发0个仍是有效采集，会累计余量并扣一次次数/冷却；只够装部分时发能装下的整数，超出整件丢弃，不存成欠账，余量始终小于1件。`hits_per_cycle` 仍按有效采集次数扣除，因此倍率2.0也会提高同一资源点每轮的总产量。原采集冷却继续生效，不修改武器攻速和距离。

每种材料的模型、色调、缩放、次数、透明保持时间和生长时间均来自 `Materials/<材料键>`。金银铜目前共用金属模型，通过颜色区分；木材使用独立模型。

## 回合恢复和实体安全

材料种类、成长进度和“本轮尚待抽签”的状态保存在逻辑资源点中。回合结束不会重新随机所有资源点；已经选定的下一轮材料继续保留，等待期间暂停进度。若资源实体意外失效，重建时恢复已选材料和进度，只有尚未执行的采空抽签会被执行一次。

新战役第一次创建世界时使用初始 `Weights`。单纯占位导致资源暂时不显示，不视为玩家采空，因此不触发重新抽取。

## 验证状态

新增 `tests/ResourceRerollProbe.inc`，由集成测试命令 `zsh_test resource_reroll` 调用。它通过单正权重确定木材到金、金到铁的多轮顺序，并检查旧材料奖励、原实体引用、颜色/缩放、透明进度、占位延期、实体失效重建、关闭重抽、初始表回退和无效权重拒绝。模型切换的实际碰撞与临时新模型参照做边界和多条引擎射线比较。

2026-10-15，独立实服资源测试全部通过，记录见 [resource_collision_real.json](../tests/reports/v03/resource_collision_real.json)。木材、铁、金各 75 条碰撞参照射线均无差异；占位边界与同材质新实体一致，且确认是模型原始范围按目标缩放计算后的范围。首次测试发现裸写缩放导致旧边界未更新，已通过先设置目标缩放、再换模型并调用原生 `SetModelScale` 刷新修复。

包含本次修改的最后一轮完整回归为 **367 项通过、0 项失败**，运行错误和更新器错误均为 0，记录目录为 [resource_verified](../tests/reports/v03/resource_verified)。367 是整个外部插件回归的断言数量；其中资源碰撞独立比较了木、铁、金共 **225 条射线**。
