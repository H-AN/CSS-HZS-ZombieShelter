## 安装

1. 准备能正常运行且包含 `Han_OnZombieDamagePre(int zombie, int attacker, int &damage)` 的 HZS 主体构建、SourceMod 1.12、Metamod，以及主体配置引用的 NPC 资源。只有源码或 include 更新、运行的主体 SMX 仍旧时，伤害成长不会生效。本仓库不包含主体 SMX，也不覆盖已有主体全局配置。
2. 主体仓库的 `示例模型材质/示例模型材质.7z` **包含 models、materials、sound**，应全部部署到服务器 `cstrike`。其中50个声音覆盖原示例配置的全部37个唯一音频路径，包含丧尸、BGM、倒计时和胜负播报；不要通过改写音效映射补救漏装资源。

6. `zombies.cfg` 默认普通池100，外部在本模式开局临时设置主体生成CVar，在退出模式时恢复原值，无须改写主体全局配置。本机测试服保留之前恢复的3份原示例 HZS 配置（全局 `max_zombie_spawn` 仍为80）；NPC音效、Vox、BGM、天空、出生倒计时、伤害显示和击杀图标保留原配置。
7. 重新加载地图。战役中修改模型、地图坐标或配置后应重新加载地图，不热换半套状态。

默认普通模板 key 为 `putong_stage1`；固定 Boss key 为 `boss_pangzi`，API 公共名字为“巨型狂暴形态僵尸”。模板变化时，一起对齐本图 Stage 与 `bosses.cfg`；配置 key 与 API 公共名字是不同字段。

没有地图配置的地图不启用外部模式，继续由主体运行原 PVE/ZE。玩家复活、全灭检查和原生补怪继续使用主体；外部没有第二套复活 timer。Boss 通关显示结局 HUD 后按地图循环换图，所有基地摧毁则提交失败并结束真实回合。

本插件自带受控的自动防御模块。使用本套设施时无需再加载旧 HZSTurret/FlameGuns 创建同一批实体。

## 玩家操作和 HUD

- 看向材料：显示名称与可采集次数。新采集源码按有效资源命中时的当前武器 classname 应用 `gather_multiplier`，未知武器回退普通刀，不检查刀槽。最终产量为材料基础 yield 乘倍率，小数按玩家和材料累计，背包只发整数；满背包不消耗次数，正倍率不足1件仍计一次有效采集。每次有效采集扣一次节点额度，最后一次显示 `0/总次数` 后隐藏。资源池可配置耗尽后重抽下一轮种类，最后一次仍奖励原材料；下轮使用新材料的模型、颜色、额度和恢复时间，同一实体渐显、成熟后恢复碰撞与额度。生长中无法采集、不阻挡。刀击继续采用引擎实际武器碰撞命中（含挥刀体积），不叠加准星直线要求。当前27159测试服已应用新采集构建；旧交付快照保留。见[采集物再生与概率配置](docs/采集物再生与概率配置.md)。
- 看向基地/设施：显示当前等级和血量。基地被丧尸攻击时增加“正在被攻击”，右侧全队警报同时列出所有受袭基地。默认最后一次受击后持续3秒；枪击不扣耐久，刀击受损建筑显示实际修复量；满血仍显示 `当前血量/最大血量`，不会继续加血。
- 在基地A/B/C对应绿色安全区内按 **E**：打开该基地菜单，查看等级、当前/最大血量和升级入口。选择升级后显示自己背包中每种材料的“已有/需要”和升级后的最大血量，再确认扣个人材料。个人材料不足时确认项不可选。无需瞄准基地墙壁。
- 基地菜单提供该基地的**共享仓库**，可把自己背包材料存入，也可取出其他玩家存入的材料；A/B/C仓库分别保存。建造或升级先把所需材料取到自己背包，再确认消费，系统不会直接扣别人背包或其他基地仓库。
- 单座已毁基地的安全区仍可避难，菜单显示已摧毁并禁用升级；只要另外至少一座基地存活，三处安全区都继续保护。三座全毁才触发失败。
- 近距离瞄准炮塔、火焰塔、围栏、地雷或增强器按 **E**，优先打开该设施菜单，即使站在基地安全区内也不会被基地菜单抢走。可查看等级、耐久、伤害、射程和下一阶材料；增强器显示四项团队伤害加成。升级、拆除都要进入确认页，操作时仍须瞄准设施且在交互距离内，默认128单位。
- 普通玩家只能升级、拆除自己建造或无主的设施；其他玩家的设施可以查看。玩家退出后其设施变为无主，队友可继续管理。管理员有独立管理入口；全局建筑列表允许远程操作，E入口仍校验近距离。
- 拆除默认返还实际投入建造和升级材料的50%，逐种材料向下取整；管理员免费调整等级不制造退款。战斗摧毁、基地毁坏和地雷爆炸不按拆除返还。退款开关、比例、管理员退款归属位于 `management.cfg/Dismantle`。
- `!build` / `sm_build` 按类别、变体、详情、确认建造；新建锚点受当前基地红框、配额及全服实体预算限制，允许基地内、顶部、坡地和设施重叠。扩大器对固定所属基地提供当前等级范围和配额贡献，不改变绿色安全区。
- `!materials` / `sm_materials` 分页查看所有已登记材料，核心与内部货币也能存取和支付费用；是否可采集由 Gatherables 定义。
- 默认黑夜在所有绿色安全区之外每秒扣 **1 HP**。安全区是基地向外扩张的768×768单位方形，按基地角度旋转，每秒刷新绿色边界；仅免环境伤害，丧尸仍可攻击玩家。
- 休眠 Boss 不主动追人，机枪/火焰塔跳过它。有效伤害使它苏醒，玩家地雷也可唤醒。日夜切换不会清除 Boss 或强制送它回家。

HUD 使用 `SetHudTextParams` / `ShowHudText` 分频道显示：

| 频道 | 内容 | 位置 |
| --- | --- | --- |
| 0 | 天数、昼夜、倒计时、基地与丧尸数量 | 右上，x=0.64 / y=0.06 |
| 1 | 个人材料、操作提示 | 右侧，阶段信息下方，x=0.64 / y=0.18 |
| 2 | 瞄准的基地/设施血量等级，或材料可采集次数 | 准星下方 |
| 3 | 本次采集、修复、满血等操作反馈 | 屏幕下部 |
| 4 | 通关/失败结局 | 中上部 |
| 5 | 全队受袭基地警报，可同时列出多座基地 | 右侧，x=0.64 / y=0.41 |

警报持续时间为 `mode.cfg/HUD/base_attack_alert_seconds`，缺省3秒，设0关闭。玩家攻击和修理不会触发丧尸受袭警报。

基地、炮塔、火焰塔、围栏、地雷、增强器都支持 `Growth/max_level` 与按级增长公式，不需要为100级逐级写100份配置。默认等级上限保留现有平衡；打开100级、属性和材料增长、单独覆盖特殊等级，以及伤害成长倍率的配置方式见[等级与阶段CVar配置](docs/等级与阶段Cvar配置.md)。

真实客户端已通过E和确认菜单把基地、炮塔从99升到100级：基地最大血量147500→149000，炮塔25000→25250，材料按显示费用扣除，100级升级项禁用。增强器中英文百分号已复验恢复。高等级截图仍有CS:S原生绿色购物车图标局部覆盖菜单操作文字，关键数值可读；此限制已记录，不能把该批截图称为完全无遮挡。新增7张资源图确认木5/5耗尽获得5木、金1/1耗尽获得1金，以及金/铁隐藏、渐显、成熟至铁4/4；场景较暗，颜色和精确透明度由运行断言确认，不单靠截图判断。35+8+7共50张视觉证据见 [ui_visual_review.json](tests/reports/v03/ui_visual_review.json)。

`destroy_summons_on_failure=0` 保留存活设施并在下一真实回合免费重建，`1` 清空。已爆地雷和战斗摧毁的设施不复活、不返还材料。升级基地保留等级和最大HP，恢复不满血；未升级基地恢复基础状态。每名玩家的个人背包、A/B/C各自共享仓库和采集成长进度在退天回合后保留，换图或服务器重启开始新战役。个人材料不会因同队玩家采集自动增加；协作通过基地仓库存取进行。

**0.3 退出规则：**玩家断线或退出后，背包先清空并转入团队共享物资，优先当前安全区对应基地，否则最近存活基地，最后选择其他基地。首选仓库满了会分流到其他仓库；全满的剩余数量进入共享“待入仓”队列，仓库材料详情中可见。取出材料腾出容量后自动回填，待入仓材料不再属于离线个人。重新连接从空背包开始，不能既恢复旧背包又再次领取同一笔入仓材料。此规则替代0.2的离线个人库存恢复；仍在服务器内的玩家跨退天回合继续保留自己的背包。

## 实体数量与建造限制

`management.cfg/Limits/max_total_buildings` 默认768，是全服逻辑设施总量（基地不计）。底层全图存储1024格含基地；每基地另算 `min(build_limit_max, 等级build_limit + 有效扩大器当前级build_limit_bonus之和)`。旧 max_managed_defenses 仍可带迁移日志读取，但迁移预览会明确改成新字段，避免旧96限制使每基地128/256失效。`entities.cfg` 的全服真实实体预留继续生效，增加逻辑配额不会绕过它。

默认建造总实体上限为**1500**；配置可以调高，但即使填写2000，加载时也会硬截到**1800**。实际门槛还取引擎可用总数减动态预留、引擎可用总数减关键余量248，与该建造上限中的最小值。动态预留默认至少248，并按 `最大玩家槽位 x 4 + (主体普通池数量 + Boss数量) x 2 + 64 + 基地数 + 采集节点数` 增加。这里按服务器最大槽位预留，不能因为当前人少就把给将来玩家和原生补怪的空间建满。

例如引擎上限2048、32个玩家槽位、80只普通池、1个Boss、3基地和32材料点时，预留389，动态门槛1659；默认1500实际生效。把配置填成2000会先截为1800，再因预留提前在1659拒绝新建造，不代表一定允许建到1800。

达到实体预算后拒绝新增，创建失败完整退款。资源成熟继续检查实际占位；已建设施恢复复用保存变换，允许原先合法的叠放，不再按旧 ClearHull 永久延迟。真人出生遍历可用安全点，候选点不再永久禁建。该预算保护约束本外部插件，其他插件创建的实体也计入当前总数。

## 中英文翻译维护

玩家可见的HUD、菜单、采集/修理提示、基地仓库、昼夜播报和结局集中在 `addons/sourcemod/translations/HanZombieShelter.phrases.txt`。使用SourceMod的 `en`（英文）、`chi`（简体中文）语言键，按接收玩家的语言分别格式化；服务器控制台按服务端语言显示。HUD分隔符使用ASCII `|`、`/`、`->`、`x`，避免中点和乘号在游戏字体中显示问号。

默认配置的 `display_name`、`victory_phrase`、`loss_phrase` 保存翻译键：材料为 `MaterialWood`、`MaterialIron`、`MaterialCopper`、`MaterialSilver`、`MaterialGold`，配方为 `RecipeTurretBasic`、`RecipeTurretHeavy`、`RecipeFlame`、`RecipeFence`、`RecipeMine`、`RecipeDamageAmplifier`，结局为 `CampaignVictory`、`CampaignLoss`。更换名称时应修改同名phrase的 `en` / `chi`，让不同语言客户端都可读。材料和配方的自定义 `display_name` 仍可写直接名称，届时按原文显示；结局 `victory_phrase` / `loss_phrase` 应填写已存在的翻译键。新增玩家文案不得在生产源码硬编码中文，管理员菜单、实体预算提示和断线入仓播报同样使用翻译。

维护 `tests/phrases_*.json` 词条源文件。目前为 `hud`、`world`、`inventory`、`management`、`economy`、`progression` 六份，共156个词条，工具自动合并，随后生成或核验：

```powershell
python .\tools\build_translations.py
python .\tools\build_translations.py --check
```

工具检查重复键冲突、中英占位与 `#format`、源码静态引用和参数数量、默认配置名称键、生产源码中文直串及不兼容分隔符；日志与注释不算玩家文案。动态材料/结局键由默认配置一并核验。若服务器自行使用直接名称，检查本地自定义配置可加 `--allow-custom-labels`。生成后部署phrases文件，并重新加载插件/地图。

## 管理员与构建

`sm_zsh_status` 查看状态。存活的游戏内管理员用 **`sm_zsh_admin`** 打开管理菜单，默认要求ROOT权限，并通过 `CheckCommandAccess` 支持 SourceMod 对该命令的权限 override。菜单每次选择都重新验权；失去权限、换回合、目标退出、建筑替换或升级后，旧操作会被拒绝。

- **重置当天：**确认后重新开始真实回合，保持当天数，回到白天倒计时，保留物资和存活设施，恢复基地。确认过程中天数变化会使旧确认失效。
- **基地共享物资：**选择基地和材料，增加/减少10或100，设0，或设置精确数量。
- **在线玩家物资：**从真实在线玩家列表选择目标和材料，支持相同操作；使用玩家serial绑定，目标离线后不会误改后来占用该槽位的人。机器人不出现在此管理列表。
- **精确数量：**先在菜单中选择“设置指定数量”，30秒内于游戏控制台执行 `sm_zsh_admin_value <数量>`，例如 `sm_zsh_admin_value 500`。只接受0至2000000000的十进制整数，并受个人/仓库容量限制；一次输入仅执行一次，打开其他管理页或回合改变后旧请求失效。
- **建筑管理：**管理员瞄准建筑按E可进入管理，基地也支持；防御设施菜单含管理员入口。可升级一级、降级一级、摧毁，均二次确认。E入口保持近距离和瞄准复核；“全部建筑列表”允许远程管理。摧毁最后一座基地会触发失败。

ROOT控制台命令仍有 `sm_zsh_phase day|night`、`sm_zsh_day <天数>`、`sm_zsh_grant <材料ID> <数量> [名字|#userid]`、`sm_zsh_fail`。材料 ID 按 materials.cfg 登记，包含核心和内部货币。`sm_zsh_grant` 未指定目标时优先本人，否则选择在场存活玩家。`sm_zsh_reload` 只允许未建立战役时重试加载。菜单面向游戏内存活管理员，RCON不能直接打开玩家菜单。

PowerShell运行 [build.ps1](build.ps1)，可指定编译器和 SourceMod include。源码入口是 [HanZombieShelter.sp](addons/sourcemod/scripting/HanZombieShelter.sp)，HUD、菜单、声音、配置、世界/NPC/战役逻辑分别维护。自动检查使用 [ShelterIntegrationProbe.sp](tests/ShelterIntegrationProbe.sp)，正式服务器应装生产构建，不保留测试SMX。

本机服务器的备份、LAN连接、RCON与恢复见[本地服务器说明](docs/本地服务器测试与恢复.md)。`server-support` 为主体源码包缺少的翻译提供兼容补充；已有完整安装应保留自己的翻译和配置。

## 接入边界

隐藏怪仍登记在主体，主体活怪统计可能包含隐藏池；外部 HUD 显示当前昼夜阶段的实际活动数量。普通怪死亡、奖励和补怪均走主体，阶段收回不会杀怪或删怪。

自动设施通过在场存活合作玩家调用主体伤害入口，奖励另按原设施主人和固定所属基地结算；材料采用个人背包与基地共享仓库结构。实体使用 EntRef，玩家使用 ClientSerial，异步回调和菜单同时检查回合 epoch 及稳定建筑标识；升级确认会重新核对区域、等级和操作者的个人材料。仓库存取也会重新校验所属基地、个人库存和容量，防止过期菜单或重复请求转出材料。建造检查射线锚点、按类姿态、当前红框/高度、NPC/Boss 显式出生柱和实体预算，不用整个基地包围盒或大片真人出生点保护禁掉内部。99999是有限的原生关卡桥接阈值，Boss是外部通关条件。
