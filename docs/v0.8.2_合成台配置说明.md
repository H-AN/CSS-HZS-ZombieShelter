## 合成台名称与等级

`workbenches.cfg` 的 `Types` 组名既是配置匹配标识，也是本轮约定的合成台名称。默认只有一个 `"合成台"` 组；`BuildRecipes` 的 `output_type` 指向这个组。不要为武器配方另外维护一套编号。

默认建筑方案：

- 每基地最多一座合成台，限制由全部合成台类型共享。
- 建造费用为木材 50、铁 20、铜 5，从建造者个人背包支付。
- Lv.1 耐久 500，每级增加 100，Lv.10 耐久 1400。
- `Growth/max_level` 为 10；各级升级费用写在目标等级的 `upgrade_cost` 中，可独立编辑。
- 必须正常供电才能合成，Lv.1 电力需求为 50，每升级一级增加 30，Lv.10 为 320；数值独立写在本台配置中，可由服主编辑。
- 模型尺寸 1.0，放置偏移为 `0 0 0.5`。该值按真实引擎模型边界 `minZ=-0.28125` 校准，已完成合法生产放置；不修改模型文件或其他建筑的贴地规则。
- 同一座合成台升级后使用该实体的新等级判断配方；其他基地的高级台不会替本台解锁配方。

升级费用与每次合成费用是两笔独立交易。从合成台的设施管理入口升级或拆除，沿用既有管理权限；使用武器或材料配方时仅支付当前玩家个人材料。

最终供电配置为 `Levels/1/power_required = 50`、`Growth/Stats/power_required_per_level = 30`，等级需求为 `50 + 30 × (等级 - 1)`：

| 合成台等级 | 电力需求 |
| --- | ---: |
| 1 | 50 |
| 2 | 80 |
| 3 | 110 |
| 4 | 140 |
| 5 | 170 |
| 6 | 200 |
| 7 | 230 |
| 8 | 260 |
| 9 | 290 |
| 10 | 320 |

供电不足时仍可查看配方和设施管理，但武器与材料合成确认均不可执行，不扣材料。升级后按该台新等级重新参与现有电网分配，可能因需求增加而暂时停机。该方案仅改变合成台自身的需求，不修改发电机产出或其他已有配置。

## 武器配方

```text
"ShelterWeaponCrafting"
{
    "schema_version" "1"
    "Recipes"
    {
        "axe"
        {
            "display_name" "斧头"
            "required_level" "1"
            "command" "sm_axe"
            "cost" { "wood" "50" "iron" "20" }
        }
    }
}
```

每个 `Recipes` 子组是一条独立配方。组名是稳定的配方标识；玩家看到的是 `display_name`。`cost` 只需写实际消耗的材料，省略项按 0，但配方必须至少消耗一种正数量材料，防止错误配置变成免费领取。

合成台要求按以下规则解释：

| 字段 | 含义 |
| --- | --- |
| 未填写 `required_station_type` | 绑定 `Types` 顺序中第一个可用合成台类型，不是不限类型，也不是地图上第一座实体 |
| `"required_station_type" "高级合成台"` | 只允许配置组名恰为“高级合成台”的类型使用 |
| 未填写 `required_level` | 最低等级为 Lv.1 |
| `"required_level" "3"` | 当前正在使用的匹配合成台须达到 Lv.3 或以上 |

“可用”是启用、配置有效且有启用的有效建造配方的合成台类型。类型名不存在或配方内容无效时拒绝该配方，不把显式要求悄悄降为默认台。增删、停用或调整 `Types` 顺序可能改变未指定台名的武器归属；需要固定归属的武器应显式填写台名。重命名合成台组时同步修改引用它的 `output_type` 和 `required_station_type`。

不同名称之间没有自动继承。例如“高级合成台”Lv.10不会自动获得明确绑定“初级合成台”的武器配方。同一名称的合成台升级，则继续满足原来较低的最低等级要求。

`command` 由服主填写，必须是单个已经注册的无参数命令名，可以使用外部武器系统注册的随机名称。带参数、空格、分号、换行或命令链的写法会被拒绝，不作为多条控制台指令执行。昼夜求生只在最终验证个人材料、台名、等级和指令可用后扣款，再以该真人身份执行一次 `FakeClientCommand`；不创建假客户端，不生成或接管武器实体。指令不存在时不能扣费。

`FakeClientCommand` 没有外部“武器已发放”结果回执，因此当前交易完成边界是“扣材料并派发一次配置指令”。外部武器系统自己的限制、背包处理及实际发放由外部系统负责；若以后要求发放失败自动退款，需要增加可确认的外部结果接口。

## 材料配方

```text
"ShelterMaterialCrafting"
{
    "schema_version" "1"
    "Recipes"
    {
        "wood_to_iron"
        {
            "display_name" "木材合成铁"
            "cost" { "wood" "100" }
            "output" { "material" "iron" "amount" "1" }
        }
        "plague_core"
        {
            "display_name" "瘟疫核心合成"
            "cost" { "gold" "10" "silver" "20" "credits" "5" }
            "output" { "material" "plague_core" "amount" "1" }
        }
    }
}
```

任意类型、任意等级的有效已完工合成台均可使用材料配方，不套用武器配方的台名或等级限制；该台仍须正常供电。一次选择执行一次完整配方：可以投入一种或多种已注册材料，产出一种已注册材料的指定正整数数量。

默认启用：

| 输入 | 输出 |
| --- | --- |
| 木材 100 | 铁 1 |
| 铁 100 | 铜 1 |
| 铜 100 | 银 1 |
| 银 100 | 金 1 |
| 金 10、银 20、生存币 5 | 瘟疫核心 1 |

扣款和产出都使用当前玩家个人背包，不自动补扣基地仓库。输入必须全部足够，产出必须能完整放入背包，否则整次拒绝，不扣材料、不截断产出。若输入中也有产出材料，容量检查按扣除输入后的净数量计算。

材料 ID 沿用 [materials.cfg](../addons/sourcemod/configs/HanZombieShelter/materials.cfg)：`wood`、`iron`、`copper`、`silver`、`gold`、`plague_core`、`credits` 等已注册条目。`credits` 是昼夜求生账本的“生存币”，不关联 CS 现金或 HZS 金钱；菜单按材料配置显示中文名称。未知材料、负数、无效数量或无有效消耗等错误不会作为免费合成执行。

## 验证边界

本轮的编译、离线配置和事务边界核验与实际引擎测试分开记录。后续运行验证只能使用已指定的固定测试 ROOT 与 27169；遵守服务端最小化、关闭原生页面并查看完整 JPEG、零 BOT／FakeClient、不重新启用失败补丁及不扩修运行换图崩溃等既有约束。
