# 按需问题库：每轮最多五项

适用范围：CSS-HZS-ZombieShelter v0.8.2 的配置解释、自然语言修改、预设初配、缺损修复与新增现有类型。先识别用户这一次要做什么，再按[工作流程](01_AI工作流程.md)定位目标；**不默认启动整套问卷**。本文件后半部分保留完整初配问题池，需要整套配置或用户点名某模块时再取用。

## 先识别当前意图

| 用户意图 | AI直接推进的内容 | 只在缺少时补问 |
| --- | --- | --- |
| 单项改值，如“榴弹炮塔一级伤害150、间隔0.2秒” | 读当前目标对应类型与等级，定位实际字段，只改所指两项并检查关联 | 目标目录、炮塔类型或等级不明确时，只问缺少的那项 |
| 预设初配，如“帮我配置轻度玩法” | 核对目标与完整基线，再按下方可选问题池接受预设或细调 | 当前未决的玩法选择，每轮最多五项 |
| 百科解释，如“施工速度在哪里改” | 给出cfg、字段、单位和作用；区分施工工效与材料造价 | 只有无法区分用户想了解的效果时才问；纯解释不索取服务端路径 |
| 修复，如“这块配置删坏了” | 备份目标，定位缺损，与同版本只读示例核对，最小修复缺损块 | 缺少原件/备份，或无法确定块边界时才问，不整套恢复默认 |
| 新增现有类型，如“再加一种机枪炮塔” | 使用现有支持的类型/配方结构，遵循[自然语言修改与新增炮塔](07_自然语言修改与新增炮塔.md)，保留其他条目 | 只补缺少的名称、模板类型、必要数值或材料方案，不转成新功能开发 |

目标已经提供、类型与等级已知、用户给了合法值时，直接定位并修改。例如“一级榴弹伤害改150”不需要再让用户选轻度/重度、人数、胜败或重新确认150。合法用户目标优先于模板；与仓库示例不同不代表用户配置错误。

## 先明确在哪里改

1. 用户给出真实服务端位置：读取并修改这个目标当前配置；文件保存与运行加载分别报告，不自动发游戏命令。
2. 用户指定任意工作目录：就在该目录维护配置副本，不要求它一定是运行服。目录已有配置时使用现有用户值；首次为空且用户要建立配置时，将同版本示例的**完整配置树**复制到该目标再应用需求，不能只生成少数模板变化文件。以后继续修改当前副本，不重复初始化。
3. 没有任何位置：只说明相对cfg、字段、建议值或用户给定值，并推荐用户提供一个目录以便代改；不擅自创建桌面目录、会话文件、备份或输出包。纯解释不需要为了提供答案而强行追问位置。

仓库示例用于只读溯源和首次空目标初始化，不能改写示例来代替修改用户目标。目标已有值、ID、注释和无关自定义全部优先保留。局部损坏先备份并只修缺损块；无法无损解析时请用户提供原件或备份，不以默认配置整份覆盖。

## 只问当前缺少的信息

每轮最多五问是**上限**，不是每次必须凑五问。通常按“目标位置→具体类型/配方→等级或作用范围→仍缺少的值”取当前确实需要的问题；答案在会话或文件里已经明确就不再问。只改某台型某级的伤害时，不扩大为所有等级，不顺手改成本、模型、供电或其他炮塔。

“把这条配方改成只要木1铁1”表示该条成本最终只含木1、铁1，旧铜银金等成本应从这条`cost`块移除；“木铁都改1，其他不动”则只改这两个叶。表述仍不明确时仅补问这一处区别。新增字段、修改等级增长、放宽数量上限等超出本次要求时，不自动执行。

单项修改、解释或工作目录副本调整，无需先完成全部安装和地图问卷。只检查本次改动实际依赖的配置约束；是否在真实服可运行另行标记。完整初配和宣称可部署时，再按[前置与地图就绪检查](02_前置与地图就绪检查.md)核对安装和已适配地图。地图位置、Boss五槽等缺失不能通过抄坐标补齐；本目录不开展录点、地图制作或资源开发。

## 对话规则

1. 每条消息最多提出 **5个独立问题**，收到本轮回答后才进入下一轮。不要把五个编号展开成几十个必须回答的子问题。最后剩几项就问几项，不凑满五项。
2. 下方是完整初配时按优先级取用的问题池，**不是单项修改的必经步骤**。已知信息、用户已明确采用模板的项目、已明确保留的已有值直接记录，跳过重复询问。一个模块可以整体采用[轻度玩法](模板/轻度玩法.md)、[重度玩法](模板/重度玩法.md)中的对应值，或整体保留现有配置；只展开用户关注的模块。
3. 需要推荐时展示“当前值（能读到时）→推荐值→作用”，给简短选项或填写例子。初配的推荐可取所选模板对应值；模板未覆盖时优先保留已检查的用户值。用户已经给出明确合法值时直接采用，不强制先接受推荐。仓库默认只作参考，不能冒充所有服务器都经过平衡验证的推荐。
4. 用户可以回答“第1项改成240秒，其余用推荐”“这一模块保留已有值”“后面所有玩法数值采用轻度模板，技术项保留”。这种明确授权可以一次解决相应范围。用户只答了两项时，其余三项仍为待答，不能因漏答、沉默或时间过去而自动采用推荐；下一条只补未决项，并解释推荐。
5. 用户说“我不懂”时，解释实际体验并给一个明确建议，让用户可以回答“推荐”。不要把专业字段名、源码细节或模型参数作为新手必须理解的内容。
6. 一组材料权重、一个按等级增长表，分别可以作为一个完整方案供用户整体选择；需要用户自行填写很多格时，按不超过五个独立数值问题继续拆轮。比如用户要逐项指定五种材料概率，就单独一轮问木、铁、铜、银、金，别再塞入刷新时间。
7. 每轮结束只简短回显已决定内容与联动提醒。有用户指定的目标/工作位置时按[配置会话](模板/配置会话.json)记录进度；无位置时只在回复中说明结果，不擅自落盘。确有未决内容才问下一轮，不能同时把下一轮问题预先抛给用户。字段、单位和限制按[配置目录与字段速查](04_配置目录与字段速查.md)核对。
8. 轻度、重度均保留当前实现要求的至少一个有效Boss。当前不提供“删除所有Boss继续启用主玩法”的选项。更换Boss类型、数量或地图时先复核已有适配与原生Stage；位置仍按前置检查处理。

## 可选初配问题池：玩法方向，最多五问

仅在用户要求整套初配或玩法方向建议时从这里取题。单项修改跳到对应字段；已知的问题省略。后续“第二步”到“第十步”均为这条可选初配路线中的模块，不是每次请求的固定流程。

| 编号 | 对用户的问法与参考 | 配置定位 |
| --- | --- | --- |
| A01 | 预计平时几名真人一起玩？可答“1～2人”“3～6人”或人数。推荐按实际常见人数，AI据此检查经济与压力；这不是插件的自动人数缩放开关。 | 会话目标；联动经济、基地、电网与怪物模块 |
| A02 | 想用轻度还是重度玩法作为起点？轻度偏宽松发展，重度偏资源取舍和防守压力；选定后可以逐项改。 | 两份模板；不直接映射一个cfg开关 |
| A03 | 白天持续多少秒？例如“240秒”；推荐所选模板值，并说明这段时间主要用于发展。 | `mode.cfg/Rules/day_seconds` |
| A04 | 黑夜持续多少秒？例如“180秒”；推荐所选模板值，并说明持续防守负担。 | `mode.cfg/Rules/night_seconds` |
| A05 | 生存到第几天提供救援胜利？可答具体天数或“关闭救援，只通过击杀全部有效Boss获胜”。推荐模板值；杀完全部Boss的胜利通路仍保留。 | `lifecycle.cfg/Campaign/survival_day_limit`；见[胜败规则](04_配置目录与字段速查.md#胜败规则) |

示例首轮输出：

> 先确定这5项：常见人数、轻度或重度、白天秒数、黑夜秒数、救援天数。每项我会显示对应推荐；你可以直接回复“1～2人、轻度，其余推荐”。后续只细问你想调整的部分。

## 第二步：失败与夜间生存

| 编号 | 对用户的问法与参考 | 配置定位 |
| --- | --- | --- |
| B01 | 失败后继续这场生存，还是判负并进入原生地图轮换流程？推荐模板方案；实际轮换是否正常仍要测试。 | `lifecycle.cfg/Campaign/failure_policy` |
| B02 | 选择继续时，失败倒退几天？“0”表示不倒退。推荐模板值；若已选直接判负则本项不问。 | `Campaign/rollback_days`、`minimum_day`保留 |
| B03 | 升级基地在失败恢复时回到多少最大耐久比例？例如“50%”。推荐模板值，AI转换为0～1小数，当前范围必须大于0且小于1。 | `lifecycle.cfg/BaseRecovery/upgraded_hp_fraction` |
| B04 | 夜晚离开安全保护是否受到暴露伤害？推荐模板方案。 | `mode.cfg/Rules/night_exposure_enabled` |
| B05 | 开启暴露伤害时，每次扣多少HP？推荐模板值；伤害间隔若未被模板授权，下一轮再问。 | `mode.cfg/Rules/night_exposure_damage` |

如需继续细化，下一轮从以下未决项中取最多五个：暴露伤害间隔、入夜提前提醒秒数、失败是否销毁玩家建筑、胜败结果显示秒数、玩家重生位置策略。推荐均采用模板或保留现有值。定位分别为 `mode.cfg/Rules/night_exposure_interval_seconds`、`warning_seconds_before_night`，`lifecycle.cfg/Campaign/destroy_summons_on_failure`、`Outcome/display_seconds`，`mode.cfg/HumanTeamPolicy/t_client_spawn_policy`。重生位置策略只在现有地图已验证的选项中选择。

## 第三步：采集经济

先说明：地图资源点抽取材料用相对权重；击杀掉落用独立概率。二者不是同一张概率表。

| 编号 | 对用户的问法与参考 | 配置定位 |
| --- | --- | --- |
| C01 | 初次生成的五种材料想用怎样的稀缺分布？推荐展示模板的一组木、铁、铜、银、金占比。可以整组采用；需要自行逐种填写时，另用一轮五问收齐。 | `resources.cfg/Pools/<pool>/Weights` |
| C02 | 资源再生时重新随机材料种类吗？推荐模板方案；关闭会保留该节点先前种类。 | `Pools/<pool>/reroll_on_regrow` |
| C03 | 每次有效采集获得多少材料？先展示模板整组产量，可整体采用；逐种自定时另拆轮。刀具和技能加成另算，不能把倍率重复加进去。 | `Gatherables/<material>/yield_per_successful_hit` |
| C04 | 每个资源节点能有效采集几次后耗尽？推荐模板整组次数；这是有效采集次数，不是最终获得的材料总数。 | `Gatherables/<material>/hits_per_cycle` |
| C05 | 各材料重新长成分别要多少秒？推荐模板整组时间；长成前额外停留等待如果要改，下一轮再问。 | `Gatherables/<material>/grow_seconds` |

下一轮再处理最多五项：额外等待 `hold_seconds`、有效采集间隔 `Gathering/cooldown_seconds`、个人每种材料容量 `Inventory/capacity`、基地仓库每种材料容量 `BaseStorage/capacity`、现有材料显示名称与说明。容量0表示使用内部数量上限，不能解释成背包总共0格；保留现有材料ID与币种归类，详见[采集与掉落](04_配置目录与字段速查.md#采集与掉落)。

如果已有`Pools/<pool>/RegrowWeights`，必须登记和检查这份独立再生分布；需要细化时，后续单独问“资源再生时要与初次生成采用不同的材料分布吗？”推荐保留已有合法分布，或按用户明确选择给出整组方案。省略该块时再生权重回退`Weights`；显式填写时整份替代，漏写材料按0，不与`Weights`逐项合并。模板只修改`Weights`而已有`RegrowWeights`保持时，不能声称再生分布已经一起改变。

## 第四步：击杀收益与材料配方经济

| 编号 | 对用户的问法与参考 | 配置定位 |
| --- | --- | --- |
| D01 | 自动防御设施击杀是否也给对应主人材料奖励？推荐模板方案。 | `zombie_drops.cfg/Settings/reward_defense_kills` |
| D02 | 普通丧尸掉落沿用哪一组独立概率方案？推荐展示模板中按怪物实际名称匹配的规则。要逐种自定就另拆五问。 | `Rules/<rule>/zombie_name, materials, chances` |
| D03 | 成功掉落时数量沿用哪一组方案？推荐模板值；不把“概率翻倍”和“数量翻倍”合并操作。 | `zombie_drops.cfg/Rules/<rule>/amounts` |
| D04 | 特殊怪与Boss的瘟疫核心、生存币等奖励采用模板，还是保留已有规则？推荐模板或现有已配置规则，缺少对应怪物时不凭空建立奖励来源。 | `zombie_drops.cfg/Rules`；`materials.cfg` |
| D05 | 现有材料合成的兑换方案采用模板还是要展开？推荐展示转换表整体采用；需要改变某条输入成本或输出数量时，再按最多五项逐轮询问。 | `material_crafting.cfg/Recipes` |

AI检查材料有实际获得途径、不会被容量卡死、不同转换不会产生意外的无限循环收益。生存币是插件材料账本，不能当作CS现金或HZS金钱。原生击杀金钱单列在怪物阶段Cvar分支。

| 编号 | 对用户的问法与参考 | 配置定位 |
| --- | --- | --- |
| E01 | 地图固定基地一级最大耐久是多少？推荐模板值；初始耐久须同时检查，不得超过最大值。 | `bases.cfg/Profiles/<profile>/Levels/1/max_hp` |
| E02 | 基地最高等级和整条升级曲线采用模板还是保留已有？推荐先展示一级到满级的HP表整体采用；要逐级填时另拆轮。 | `Levels`、`Growth`；见[基地与建筑等级](04_配置目录与字段速查.md#基地与建筑等级) |
| E03 | 基地升级成本采用模板还是展开？推荐展示每级所需材料表；按用户明确要改的单项继续。 | `Levels/<level>/upgrade_cost`、`Growth/UpgradeCost` |
| E04 | 新建筑需要刀具敲击施工，还是直接建成？推荐模板方案；已有施工物的变化另按生效规则核对。 | `mode.cfg/Rules/real_construction` |
| E05 | 普通刀每次施工增加多少HP？推荐模板值；维修与刀具倍率独立，下一轮再细问。 | `weapons.cfg/Weapons/<entry>/construction_hp_per_hit`，以`classname=weapon_knife`定位实际条目 |

后续未决项按顺序每轮取最多五个：普通刀维修HP；已安装各刀具的施工/维修/采集方案；每基地建筑数量配额；基地建造范围的水平大小；自建基地允许数量及各现有类型的造价/耐久；拆除返还比例；管理员拆除返还给谁；退出时材料转仓提示；全服逻辑建筑配额。各自是单独决策，不要求同条消息填完。推荐模板或保留已有值，字段见 `weapons.cfg`、`bases.cfg`、`shelters.cfg`、`management.cfg`。

固定地图基地的坐标、安全盒、出生点、建造区中心和高度边界属于地图适配资料，仅读取检查。需要修改位置时退出本流程等待适配处理。实体预算、全服上限通常保留保守基线，不因“重度”自动提高。

按需后续逐轮处理：白天放行批量/间隔、夜晚批量/间隔、普通怪攻击建筑间隔、各现有BossHP、Boss建筑伤害、Boss建筑攻击间隔、玩家和设施对普通怪/Boss的伤害成长。每个独立数值或整条已展示曲线占一问，始终不超过五问。Boss类型、数量改变须有用户明确意图并先通过已适配定义与Stage一致性检查；不在这里问五点位置。

用户需要复活等待、原生金钱、伤害数字、击杀图标或原生购买时，再展开阶段Cvar分支，每轮最多五个独立选项。仅使用[速查允许的七个阶段Cvar](04_配置目录与字段速查.md#怪物天数与伤害)，不自行写命令链或加入任意服务器Cvar；不把合成台接成B购买。

## 第七步：电网与设施

| 编号 | 对用户的问法与参考 | 配置定位 |
| --- | --- | --- |

| G02 | 缺电时按优先级停部分设施，还是整网所有正耗电设施停机？推荐模板方案。 | `power.cfg/Rules/overload_penalty` |

| 设施族 | 用户可选择的玩法效果 | 文件 |

| 等离子炮塔 | 充能、命中伤害与已有持续伤害场 | `plasma_turrets.cfg` |

| 增伤器 | 玩家/设施分别对普通怪/Boss的四路加成 | `amplifiers.cfg`、`progression.cfg` |
| 扩大器 | 建造范围加成、建筑数量加成 | `expanders.cfg` |
| 照明 | 光照半径、亮度、耗电；保留白天关灯和手动关闭规则 | `lights.cfg` |
| 信标 | 耐久、造价、耗电、已有标记外观 | `beacons.cfg` |
| 瞭望塔 | 耐久、造价、解锁等级；已有上下塔几何参数保留 | `watchtowers.cfg` |

设施展开使用这一组最多五问，缺项就少问，已知项跳过：

1. 这一类现有哪些类型允许建造？推荐保留现有完整目录；用户可明确禁用某配方。
2. 建造成本采用哪组方案？推荐所选模板；逐项自定再拆轮。
3. 耐久与升级曲线采用哪组方案？推荐所选模板。
4. 这一类的主要功能数值采用哪组方案？只呈现该类实际支持的效果，例如恢复量或伤害，不把不支持的属性添加到文件。
5. 解锁等级采用哪组方案？推荐所选模板；耗电/优先级已在电网模块决定的直接沿用。

“改成25伤害，其他保留”即是明确答案。需要自定升级成本、特殊攻击周期、组限或光色时，再从[设施速查](04_配置目录与字段速查.md#电网与各类设施)提取最多五个单项。不得通过复制一个通用字段表给所有设施添加无效功能。信标每基地一个是实现约束，不提供改成多个的配置承诺。

## 第八步：技能与篝火

| 编号 | 对用户的问法与参考 | 配置定位 |
| --- | --- | --- |
| H01 | 是否开启角色技能？推荐模板方案。 | `skills.cfg/Rules/enabled` |
| H02 | 每到一个新的最高生存日发多少技能点？推荐模板值；已过去天数不补发。 | `skills.cfg/Rules/points_per_day` |
| H03 | 现有13项技能的等级、每级效果与点数成本采用模板还是展开？推荐展示可买满的实际效果表；展开后按技能逐轮问。 | `skills.cfg/Skills` |
| H04 | 洗点需要哪些已有材料？推荐模板成本表；从个人背包扣除。 | `skills.cfg/Respec` |
| H05 | 篝火的保护范围与现有等级曲线采用模板还是展开？推荐模板；仅提供夜间暴露保护，不是无敌区。 | `campfires.cfg` |

技能逐项展开时，每轮最多问该技能的启用、最高等级、每级效果、升级点数成本、该技能实际支持的间隔/半径/概率上限中的一个；仍有未决项则下一轮再问。没有半径或间隔的技能不问该字段。13项为采集、维修、施工、移速、重力、黑夜免疫、队友医疗、队友护甲、建筑维修、自疗、自护甲、生命上限、护甲上限。

篝火继续按未决项每轮取最多五个：耐久、耐久衰减量、衰减间隔、满级是否免衰减、燃料容量、每木材加燃料量、每次添柴木材成本、建造升级成本、火焰/安全圈显示。燃料消耗固定每游戏秒1，不制造“燃料消耗速率”新字段。耐久衰减与燃料是两套状态，关闭耐久衰减不会自动取消燃料要求。

| 编号 | 对用户的问法与参考 | 配置定位 |
| --- | --- | --- |
| J01 | 安全区与建造区的提示样式保留现状还是调整？推荐保留；用户要调时逐项问显示开关、颜色、线宽等已有字段。 | `mode.cfg/SafeZoneDisplay`、`BuildZoneDisplay` |

| J05 | 已适配的昼夜环境效果保留现状还是关闭？推荐保留已检查方案。需要改天空也只使用现有可用资源；地图光照合同不在本流程制作。 | Environment独立配置；见[显示声音环境](04_配置目录与字段速查.md#显示声音环境) |

完整初配结束时，按04目录逐文件登记结果：`用户自定 / 采用轻度模板 / 采用重度模板 / 保留已有 / 不适用或未启用 / 待解决`，并列出实际目标值。“不适用或未启用”在会话JSON中对应`not_enabled`，须有已确认依据；未知、漏配或缺少前置不能这样标完成。实体余量、地图几何、原生桥接和资源路径等可记录为“检查后保留”。单项修改的其他模块标`not_in_scope`，无需全部登记。配置文本、完整工作树、部署前置和实际加载分别记录：离线副本可以完成本次改值，但有待答项或配置约束失败不能称本次修改完成；安装或地图缺项不能称可部署。

单项修改完成后，只报告本次目标文件、旧值→新值、必要联动与生效条件，不追加整套问卷，也不要求用户为了收尾重新安装插件。完整初配或需要交付时，再按[检查交付与测试微调](05_检查交付与测试微调.md)办理对应范围。后续反馈“木材太少”“第一晚压力过大”时，回到相关模块，只问当前诊断所需的最多五项，保留其他已决定的配置。
