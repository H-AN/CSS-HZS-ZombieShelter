# 按天设置丧尸数量和主体 Cvar

配置位于 `addons/sourcemod/configs/HanZombieShelter/days.cfg`，普通池总量位于 `zombies.cfg`。外部模式管理数量与昼夜放行，普通丧尸的创建、死亡补充和索敌继续使用 HZS 主体。

| 天数 | 白天普通怪目标 | 黑夜普通怪目标 | 阶段 hzs_maxzombiespawn |
| --- | ---: | ---: | ---: |
| 第 1 天 | 8 | 50 | 50 |
| 第 2 到 4 天 | 10 | 80 | 80 |
| 第 5 到 9 天 | 12 | 90 | 90 |
| 第 10 天起 | 12 | 100 | 100 |

这些数量不包含固定 Boss。默认 `NativePool/initial_ordinary_count` 和 `Population/raider_alive_limit` 均为 100。白天保留少量普通丧尸，其余活体隐藏在地图外；夜间按配置分批传送至通过碰撞检查的 T 出生点。黎明收回超出白天目标的普通怪，Boss 保留。

## 主体 Cvar 的实际作用

只读核对当前 HZS 源码：`HanZombieScenarioEvents.inc` 的 `SpawnRoundZombie()` 在原生回合开局读取一次 `hzs_maxzombiespawn`；`RebornZombie()` 在尸体清理后补充一个普通丧尸，不读取这个上限。主体没有为这个 Cvar 注册动态增减现存 NPC 的回调。

因此运行中把该 Cvar 从 50 调至 100，本身不会多生成 50 个丧尸；从 100 降到 50 也不会删除原来的 50 个。外部模式采用以下时序：

1. 回合准备期间将原生开局数量设置成完整池 100。
2. 主体 `Timer_ToCreateZombie()` 先发送 `Han_OnGameStart`，然后才执行 `SpawnRoundZombie()`。外部插件在这个通知里保持 100，确保主体确实生成完整池。
3. 下一帧确认仍属于当前回合后，套用当天 Cvar，例如第 1 天 50。此时仍存在 100 个普通池实体，另外有独立 Boss；白天只放行 8 个，其他 92 个隐藏。设置成 50 没有缩减实体池。
4. 夜间最多放行当天目标和阶段上限允许的数量；后期从同一个原生池放行至 80、90、100。死亡补充仍由主体执行。

实体预算根据完整池 `gNativePoolSize + gBossCount` 计算预留，不能根据当天活动数量缩减预留。当前普通池配置上限由 NPC 跟踪预算限制为 124，为尸体、替补与 Boss 留出空间；默认 100。

## 修改一个天数范围

例如在某个 `Stages` 范围内：

```text
"night_target_alive" "80"
"day_target_alive" "10"
"Cvars"
{
    "hzs_maxzombiespawn" "80"
    "hzs_playerreborn" "15.0"
    "hzs_killmoney" "400"
}
```

`night_target_alive` 是希望夜间同时活动的普通怪数量，`Cvars/hzs_maxzombiespawn` 同时成为外部放行的阶段上限。最终夜间数量取目标、增长上限、阶段上限和全局上限的最小值；白天取 `day_target_alive` 与阶段、全局上限的最小值。希望夜间达到 100，应同时准备至少 100 的池、全局上限、该范围目标和阶段上限。

`extra_alive_per_day_after_from` 可逐日增加夜间目标，`night_target_cap` 设置增长上限。增长值不能为负，上限不能小于范围初始夜间目标或超过全局上限。计算在乘法前饱和，超大的天数也不会发生整数溢出。没有配置 `Cvars/hzs_maxzombiespawn` 的旧范围继续使用全局数量上限。

每次进入白天、进入黑夜、失败退天都会重新应用该范围的 Cvar。管理员重置当前天数会先结束并重建回合，完整池启动后恢复同一天的配置。原值只在进入模式时快照，后续启动池和阶段值不会覆盖这份快照。换图、卸载和世界创建失败的退出路径均恢复原值。

## 允许的主体选项

| Cvar | 配置范围 | 主体实际读取时机 |
| --- | --- | --- |
| `hzs_maxzombiespawn` | 1 到完整普通池数量 | 主体仅开局读取；外部另将它用于当前阶段放行上限 |
| `hzs_playerreborn` | -1、0，或 1 到 600 秒，可小数 | 下次为真人建立死亡复活计时；已有计时不重排，主体正数倒计时取整，-1 禁止，0 走即时复活路径 |
| `hzs_killmoney` | 0 到 1000000 整数 | 下次击杀结算 |
| `hzs_maxmoney` | 1 到 1000000 整数 | 下次击杀结算/玩家进入时；不会主动削减已持有余额 |
| `hzs_showdamage` | 0 或 1 | 下次主体处理丧尸受伤显示 |
| `hzs_enablekillicon` | 0 或 1 | 下次主体生成击杀图标 |
| `hzs_allowbuy` | 0 或 1 | 下次玩家购买命令 |

默认只设置数量，不覆盖原有音效、亮度、音乐、普通怪定义或其他主体配置。可选 Cvar 未配置时保留主体原值；某范围设置了可选项而下个范围省略时，恢复进入模式时的原值，防止沿用上个范围。当前主体没有提供某个白名单 Cvar 时会跳过该项，外部阶段人数限制仍按配置执行。

其他 Cvar、插件开关、胜负开关、服务器命令，以及部分可解析的数字或命令文本均拒绝加载。应用使用 `ConVar.IntValue` / `FloatValue`，恢复使用原值 `SetString()`，不拼接 `ServerCommand`。

## 验证

测试专用 `DayPopulationProbe.inc` 通过 `zsh_test day_population` 验证四个阶段、退天、启动通知的时序保护、旧回合回调无效、数值范围、白名单、可选项跨阶段恢复、退出恢复、重复退出幂等和 Boss/实体池不受影响。该测试恢复所有借用配置、当前 Cvar 和快照，不创建或杀死 NPC。

真实夜间 80/90/100 的放行与黎明收回另由本地联合服务器测试执行。以本次生成的测试报告为准，不能只凭 Cvar 数值变化宣称已有相同数量的活动丧尸。
