# AI工作流程：按需定位、直接修改、保留用户数据

适用v0.8.2。字段百科见[04](04_配置目录与字段速查.md)，常见操作见[07](07_自然语言修改与新增炮塔.md)。用户从任何需求进入，不强制重走整套问卷。

## 1. 识别本次任务

| 意图 | 动作 |
| --- | --- |
| 查询位置／含义 | 给cfg、完整KV路径、单位、作用与关联；只问说明不自动写文件 |
| 修改已有配置 | 识别真实目标和类型／等级，只问缺项；明确合法值直接最小修改 |
| 轻度／重度或整套初配 | 确定目标和来源，必要时复制完整示例，确认必要偏好后合并已接受建议 |
| 修复损坏 | 保存现状，对照用户历史和只读仓库参考，局部修复并保留自定义 |
| 新增支持的类型 | 使用真实支持结构，建立独立类型与配方，补齐必要属性；见07 |

“一级榴弹塔伤害150”不要求先选择轻重、人数或所有模块。

## 2. 三种位置模式

### 真实服务端位置

只读核对用户给的路径和层级。服务端根、cstrike、addons/sourcemod/configs、HanZombieShelter或具体cfg均按实际结构识别，不反复追加目录。

现有用户配置是编辑基准。备份本次相关文件，按已授权要求最小修改、读回检查，其他数据保持。写磁盘不自动授权结束战役、重载、切图或重启。

### 指定工作目录

就在指定目录维护副本，不转去真实服或默认桌面目录。

- 已有配置：继续编辑当前副本，保留自定义，不重新复制默认。
- 用户提供已有自定义副本并要求复制：以该副本为来源，保留其数据。
- 首次空目录且要求配置：复制匹配版本仓库示例的完整HanZombieShelter树和子目录，再调整。其他已提供且本任务需要的Environment／HZS配置另列来源与范围，缺地图资料不能伪造。
- 空目录默认形成“工作目录/addons/sourcemod/configs/HanZombieShelter”。目标已是配置目录时保留其层级，不另套一层。
- 同名文件冲突先保留并比较。少数缺件只在确认版本和缺失性质后补入，不用目录覆盖替代合并。

示例不可用或版本不明时询问参考来源，或先给字段说明。不能从模板JSON或记忆重建整套cfg。

### 没有任何位置

直接给相对cfg、完整字段、适用对象、目标值和关联。例如：

~~~
addons/sourcemod/configs/HanZombieShelter/mode.cfg
ShelterMode / Rules / day_seconds = "100"
ShelterMode / Rules / night_seconds = "100"
~~~

推荐用户给一个工作目录或真实配置位置让AI代改。不要只索要路径而漏答字段；不猜位置、不把源码仓库当目标、不创建默认输出／会话文件、不声称已改。

目标不可访问时说明能力边界并按此模式回答。已给有效位置可沿用，后来提供位置则切换相应模式。用户不愿提供真实位置时可只给工作目录，不要求密码或远程账号。

## 3. 来源只读与用户数据保留

区分仓库参考、当前用户目标、本次备份与候选。仓库示例只用于溯源、结构查询和修复对照；当前用户配置是后续编辑基准。

规范化实际路径，确认目标不同于仓库示例，且不经符号链接／目录联接写回示例。用户给了仓库原件时说明来源只读并推荐另给副本目录，不能先改仓库再复制。

用户曾改白天150、炮塔180，随后只改篝火，前两项保持。合法自定义ID、条目顺序、注释、无关设置和未知既存扩展字段优先保留；与默认不同不算错误。

首次复制记录版本、来源和哈希；后续记录目标前后哈希与差异。仓库更新不自动重铺用户树。

## 4. 最少补问

每轮最多五个独立问题，等答再继续，不凑数。能从文件和上下文识别就不问。只问本次的目标类型、等级、作用范围或缺少数值。

明确“只需木1铁1”时，选定配方cost最终只含两叶；其他材料注册及配方不动。“木铁各1其他不动”则只改两叶。含糊时仅澄清这一处。

0.2秒是每秒5次；若当前2.5秒而用户同时说“更慢”，需确认方向与数值。用户给合法明确值不强制接受模板推荐；模糊要求可建议，未答不算同意。

[03问题库](03_五项一轮问题清单.md)按需使用。单项修改不要求全量安装问卷或所有模块验收；整套配置可接受“其余采用轻度建议，其他现值保留”的明确授权。

## 5. 预设与完整工作树

模板是候选参数。空目标先复制完整示例，已有用户树只合并接受范围。expected_baseline是溯源值，不是强制复位条件；用户当前合法值不同，应记录当前值并按接受范围修改，无关数据保持。结构、阶段范围或类型不同时映射实际对象，不强加旧名称。

模板set仅作用于指定既有叶；用户另行新增类型、删除选定成本叶等按07处理，62项不是能力上限。

真实服完整树已存在；工作目录完整树持续维护。完整导出来自当前用户树，未变原字节保留，另附增量则说明依赖。不能只交几份变化文件称整套，也不让用户从备份拼装。

无位置可以解释和建议，不能将示例偷偷复制到未知目录。

## 6. 用户改坏后的局部修复

1. 原样备份坏文件和可读自定义，不立即套默认。
2. 对比当前文件、最近正确副本／备份与匹配版本仓库参考。示例说明结构，不证明所有用户数值应等于默认。
3. 能确定引号、重复键、错误类型、缺失块或引用时，只修本次确认范围，其他合法设置保持。
4. 已删除且无历史可恢复的用户值标未知并询问，不把默认冒充原值。
5. 严重损坏不能可靠解析／保留时，停止猜修整文件，请用户给备份或明确恢复范围。整套复位须用户明确要求，仓库仍只读。
6. 写回前检查是否又发生用户修改；恢复本次备份也须目标仍匹配本次写后哈希，避免抹掉后来数据。

可选字段缺省不自动算损坏。记录修复依据、保留与无法恢复项，修好语法不代表已加载。

## 7. 前置与能力边界

按[02](02_前置与地图就绪检查.md)做任务相关检查。独立解释、改值与离线修复可以处理；首次整体开服或要求可运行时需核对插件、资源、地图、本图Boss指定位置及定义／Stage。缺项阻塞部署就绪结论，不阻止无关字段说明。

不开发地图、寻找坐标或编造审计。新模型只配置现有机制支持的类型；超出机制时说明缺少支持，不添加无效键冒充实现。本任务不自动操作源码、SMX、BSP、NAV、gamedata、引擎补丁或游戏命令。

## 8. 回复与续配

简述目标或仅说明模式、对象、文件、原值→新值、保留范围、检查及生效条件。实际写回读回才说已改。

有位置时按[05](05_检查交付与测试微调.md)记录；无位置只在对话说明。单项允许其余模块未涉及；整套预设才登记所有采用／保留范围。续配读取当前用户文件和历史，不重放旧模板、不重新复制。旧记录迁移只补元数据，保留已有答案、目标、自定义与历史。

旧v1记录先保留原记录，再补v2当前状态，不能只改schema后丢失旧值。旧target.mode的local_accessible不能仅凭名称判定真实服还是工作副本，要依据用户原授权归一化为server_directory或work_directory；relative_offline也不能自动获得写入目录，有明确工作目标才映射work_directory，否则explain_only并只补问必要信息。旧storage.record_relative_path保留；只有知道原记录根时才解析为record_path，未知不猜。旧delivery.kind的complete_relative_files/local_written按实际交付范围和证据映射，旧files_complete只说明变化文件完整，不能据此将full_configuration_tree_complete或real_deployment_ready设为true。旧哈希也须区分仓库参考与用户实际文件，不重算或伪造为已核对现场。
