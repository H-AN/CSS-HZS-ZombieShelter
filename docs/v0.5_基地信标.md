# 基地信标

基地信标是可升级的普通设施，沿用 Types／BuildRecipes 变体、材料费用、维修、拆除与基地配额。新增枚举只追加，不修改旧枚举。`beacons.cfg` 根为 `ShelterBeacons`，示例使用已经过本项目真实 prop 用例的 stock `models/props_lab/reciever01b.mdl`，无新增模型下载。

每基地所有信标变体合计最多一座。存活逻辑建筑尚待恢复实体时仍占位；断电、离线主人或新建另一个变体不能绕过上限。升级已有信标不新增建筑，也不提供旋转操作。配置示例两级耐久 500／800，耗电 10／12，费用完全可配；旧服缺少新配置组时不因此停用整套插件。

存活真人在实际 E 交互距离内瞄准现存信标，可进入菜单与管理。源信标缺电或所属基地被毁时给明确原因，目的地项禁用，但仍能返回真实管理页升级或拆除。传送需要源信标、固定所属基地与供电均有效；列表只列其他存活基地的有效有电信标，不列自己所属基地。只有一个有效基地时仍可管理，不能传送回自己。传送不要求主人权限，管理继续沿用原设施权限。死亡、观众、SourceTV／Replay、BOT 和 NPC 不作为旅行者。

传送点击绑定并重验 nonce、客户端 serial、回合 epoch、配置 revision、源信标 UID／实体代次、源基地 UID／代次、目的基地 UID／代次及目的信标 UID／代次；同时再次检查源瞄准距离与两端供电。失电、基地被毁、信标被拆或重建、菜单重放均拒绝传送。管理项保留源身份和实际瞄准校验，独立于供电与基地存活；管理 token 仅目的地 core 的 `-1` 哨兵允许有符号解析，其他字段不能用负数绕过。`power.enabled=0` 沿用原无电网策略，但信标仍固定属于自己的建造基地，不借其他基地电网。

传送调用现有 `TeleportPlayerToBase(client,core)`：指定基地安全区、玩家 hull、落地支撑与占位检查全部复用；找不到落点时返回失败并保留原位置，不换到另一基地。没有新增普通玩家无来源传送命令。菜单的“管理此信标”真正返回 `ShowDefenseMenu(client,b)`，继续执行原瞄准与权限检查。

标记参考已读取的 `D:\github\git\css\H-AN-CSS-ZipLine\han_zipline.sp` 中 `CreateAdminZiplineMarker`／`Hook_AdminZiplineMarkerTransmit`。使用该仓库原 `sprites/wh_frame.vmt` 和 VTF，原 VMT 的 `$ignorez=1` 保持；本模块不伪造纹理。`Marker` 可配 sprite、局部 offset、scale、RGB、alpha；缺失或局部视觉配置无效只停用标记，不停用传送。素材由主集成步骤复制并核对原文件哈希。

每信标最多一个共享 env_sprite，模块独立保存 EntRef、UID、代次、epoch、revision 与实体索引映射，不占用灯具 `effectRef`。最多 `MAX_CORES` 个标记，创建前后检查全服 optional 实体预算，预算不足约一秒后重试。`SetTransmit` 只允许存活真人接收有效标记，实体索引直达所属槽，不扫描全世界；红绿框规则不改。标记请求全局传输并使用原忽略深度材质。[probe02 视觉复核](../tests/reports/v05/support_buildings/probe_02/visual_review.json) 已实际看到基地 A/B 不透明屋顶和 C 金属墙后的蓝色原标记，并由真实服务器射线确认墙面遮挡；该证据覆盖三个近距离遮挡视点，任意远距离 PVS 与真人多人接收仍待验。

集成接口：`LoadBeaconSettings()`（配置完成）、`BeaconCount(core,exclude=-1)`（建造限制）、`ShowBeaconMenu(client,b)`（E／管理返回）、`SyncBeaconMarker(b)`（创建、恢复、升级、供电事件）、`RemoveBeaconMarker(b)`（单座移除／销毁）、`ClearBeaconMarkers()`（回合清理／停用／卸载）、`ResetBeaconClient(client)`（断线清理）、`BeaconTick(now)`（原 0.25 秒世界节奏）。没有 OnGameFrame 或新的全世界高频 timer。

`tests/BeaconProbe.inc` 提供逻辑及真人用例，已构建并在 [probe02](../tests/reports/v05/support_buildings/probe_02/session.json) 执行，整套本轮回归实际 **307 通过／0 失败／0 跳过**；其中信标逻辑 41 项、实际姿态 1 项、额外真人边界 14 项通过。实际 E 菜单完成 A→B、B→C、C→A 的指定基地落点验证，包含清空速度、真实 hull 与落地支撑、不重复扣料；B 菜单原截图明确列出基地 A、基地 C 和“管理此信标”。菜单 nonce、serial、两端 generation/等级、失电、升级后旧菜单失效、基地毁坏及无安全落点拒绝均有实际断言。全程一名普通 Steam 真人，零 BOT，不创建或复活 NPC。

probe01 的真实照明父子变换失败记录保留；照明已在 probe02 修正后通过本地与延迟真实绝对坐标检查。信标 HUD 重复刀修复提示已在截图后修正双语词条，最终留服会使用更新翻译，截图仍保留拍摄时文本。

后续 [live_03 补验](../tests/reports/v05/support_buildings/live_03/session.json) 独立 **18/0/0**。真实基地 A 经生产 `DamageBuilding` 从 1250HP 耗尽并移除实体后，A 发电 350→0、分配 20→0，信标失效且标记映射立即撤回；五次 0.1 秒轮询内确认旧基地和 sprite 实体均已物理删除。B 仍发电 350、分配 5，另两座基地存活且没有全灭结局。`power.enabled=0` 不绕过 A 的毁坏状态，无法传入 A，不能修复复活、升级或在 A 新建；该损毁测试局随后丢弃。

同一补验以生产 World Timer 从现有原生池达到日间活动 100、夜间活动 250，原生登记 251、Boss 不变并完整还原夹具。人口观察使用真人 god/noclip、NPC 禁伤/攻击延后、建筑临时 10000000HP 等保护，仅验证实际放行，不属于正常战斗难度或负载验收。

信标及现有 `HZSH_TeleportPlayerToBase` / `HZSH_ShowBaseTeleportMenu` 不新增收费系统：选择 API 只回调 UID，商店自行检查余额并在传送返回 true 后扣费，取消和失败不扣费。音效仅核对恢复设施的文件与触发路径，未主观听音。最终交付正式留服已确认 [manual_handoff_final/session.json](../tests/reports/v05/support_buildings/manual_handoff_final/session.json)；真人多人、任意远距离 PVS 和每基地 128/256 座正常战斗负载仍待验。
